# ТракSOS

Маркетплейс выездной помощи грузовикам в Санкт-Петербурге и Ленобласти: SOS-вызов электрика, диагноста, эвакуатора; заявка мастеру приходит как звонок.

## Что внутри

| Папка | Что это |
| --- | --- |
| `server/` | API на Node.js 22 + PostgreSQL 16, WebSocket для чата и вызовов |
| `web/` | веб-приложение: клиент, водитель, мастер, эвакуаторщик, админ (React, сборка esbuild) |
| `e2e/` | сквозной сценарий в браузере: вход → SOS → вызов мастеру → «Беру» → чат → сумма → отзывы |
| `android/` | приложение для RuStore: сайт внутри, пуши, вызов на весь экран |

**Как проверить страховку прямо сейчас:** войдите клиентом `+79000000002` → «Гараж» → раскройте Scania → «Страхование / техосмотр» → отправьте тестовую заявку. Откройте вторую вкладку в инкогнито, войдите администратором `+79000000001` → вкладка **«Страхование и ТО»** в админке. Переведите заявку в «На рассмотрении», затем в «Передана партнёру», выберите тестового страховщика и нажмите «Передать страховщику». В третьем окне войдите под `+79000000041`: заявка появится в его кабинете. После оформления/отказа вернитесь к истории автомобиля у клиента. Прямая ссылка внутри **уже запущенного стенда**: добавьте к адресу сайта `#/admin?tab=vehicleServices` (вход под админом обязателен).

**Отдельный кабинет страховщика теперь есть.** Вход: `+79000000041` → «Войти по номеру» → «Кабинет страховщика». В демоданных есть назначенная заявка по DAF. Страховщик видит только назначенные ему заявки на **страхование**, может отметить оформление полиса с датой окончания или отказать с обязательной причиной. Другие страховые заявки, техосмотр и административная очередь недоступны. Это тестовая модель работы партнёра, не подключение к настоящей страховой компании и не автоматическая выдача страхового полиса.

**Если снова видна старая версия:** проверьте в Codespaces название ветки — должно быть `feature/vehicle-insurance-workflows`. Существующий Codespace, созданный из `main`, не переключается на новую ветку сам. Для надёжности создайте новый Codespace по кнопке выше. В существующем Codespace нужной ветки можно перезапустить окружение; при запуске `.devcontainer/start.sh` подтягивает изменения текущей ветки. Если приложение не открылось, смотрите терминал и лог сервера `tail -n 100 /tmp/traksos.log`.

Зелёные проверки GitHub Actions означают, что тесты и сборка прошли; **это не публичная ссылка на запущенный сайт**. Для просмотра страниц используйте Codespaces и порт 8080. Демоданные хранятся в базе вашего стенда, поэтому тестовые заявки разных Codespaces не общие.

### Как посмотреть сайт до регистрации

Откройте тестовый стенд по ссылке выше, затем в его адресной строке перейдите на `#/about`. Появится **открытая страница «Возможности»** с переключаемыми примерами кабинетов клиента, автопарка, исполнителя и сервиса. С неё можно перейти к входу или инструкциям. Для этого не нужен тестовый номер.

На компьютере (ширина окна от 1051 px) у пользователей после входа есть постоянное боковое меню. На телефоне в браузере сайт использует верхнюю навигацию, а в Android-приложении сохраняется нижняя панель.

## Кабинет рембазы на компьютере

На главной рембазы одновременно видны текущие запросы, ожидаемые машины и техника в ремонте, а рядом — быстрые ссылки на **финансы**, **карточку сервиса** и **поддержку**. Списки записей остаются в отдельных вкладках. На маленьких экранах эти блоки идут последовательно; Android сохраняет прежний компактный сценарий без дополнительной панели.

## Рабочие веб-кабинеты: исполнитель и страховщик

При открытии в браузере на широком экране кабинет исполнителя делится на две рабочие области: слева управление статусом на линии, справа активные заявки, доступные заказы, начисления и быстрый переход к финансам. На мобильном экране и в Android-приложении те же действия расположены последовательно.

Страховой партнёр входит под тестовым номером `+79000000041` (в демо-контуре) и попадает в **кабинет страховщика**. В нём есть поиск автомобиля и фильтры по ожидающим и завершённым заявкам. Кабинет показывает только назначенные этому партнёру обращения, без доступа к финансовым данным автопарка или общей админке. Водителю и владельцу доступны собственные страховые обращения через историю машины.

## Финансовый кабинет на сайте

Владелец автопарка может открыть **«Финансы»** в боковом меню или **«Расходы по машине»** из карточки автомобиля. На компьютере история отображается таблицей с датами, заказчиком, исполнителем, работами и суммами; на узком экране — карточками. Есть фильтры по машине и состоянию оплаты, а также **скачивание CSV** для Excel. Экспорт содержит только операции, которые сейчас отфильтрованы.

**Учёт:** согласованные суммы и подтверждённые системой платежи — разные показатели. Отдельно отражаются возвраты и суммы, ожидающие подтверждения. Наличные платежи вне системы не считаются банковским подтверждением. Для просмотра данных необходим вход владельца — водитель не получает права читать финансы компании.

## Новая презентационная веб-версия

В актуальной рабочей ветке на **широком экране** главная страница открывается как веб-сервис. До входа доступны:

- Понятный главный баннер с двумя действиями: вызвать помощь или войти в кабинет.
- Интерактивные промо-слайды **«Клиент / Автопарк / Партнёры / Сервис»** — показывают типовые экраны и сценарии, без вымышленных заказов или платежей.
- Понятное объяснение возможностей, блока для мастеров и рембаз и ссылок на инструкции.
- Адаптивное оформление для ноутбуков, планшетов и телефонов.

После входа на компьютере кабинеты клиента, владельца парка, исполнителя, рембазы, страховщика и администратора используют **сайдбар с разделами**, широкую рабочую область и компактные карточки. В админке есть дополнительное меню рабочих очередей. У Android-приложения своя мобильная навигация.

**Как увидеть изменения:** открывайте Codespaces по ссылке рабочей ветки в начале README и используйте браузер с окном шире 1050 px для двухколоночных кабинетов. Полностью обновлённый дизайн пока находится в разработке: отдельные экраны постепенно приводятся к единому стандарту.

### Профиль и общее меню

Кнопка **👤 Профиль** находится справа внизу Android-приложения, а на сайте — в верхней панели. В профиле основные данные и выход расположены отдельно, а роли, поддержка, документы и предложения улучшений раскрываются по необходимости. Поля компании отображаются клиенту-владельцу, а чужие функции не должны загромождать профиль страховщика или администратора. Для остальных разделов используется единое меню.

## Проверка узких экранов

На мобильном сайте (ширина 360–390 пикселей) верхняя панель содержит логотип, уведомления, общее меню и профиль. Отдельная кнопка справки скрыта только из шапки — инструкция остаётся доступной через **Меню → Как работать с ТракSOS**. В Android-приложении профиль расположен крайней правой кнопкой внизу.

Автоматические браузерные тесты дополнительно проверяют **вошедшего пользователя** на 360 и 390 пикселях: наличие кнопки профиля, отсутствие горизонтального переполнения и переход в профиль. Этот тест дополняет проверку широкой веб-версии и отдельный сценарий Android WebView.

## Единые правила интерфейса

В Android-приложении **профиль находится крайней правой кнопкой нижней навигации**, независимо от роли. Пункт «Меню» ведёт к помощи, инструкциям, условиям и предложению улучшений. На сайте профиль и общее меню доступны справа в верхней шапке, а на широких экранах рабочие разделы — в боковой панели.

Русские подписи должны оставаться целыми: элементы умеют сжиматься, длинные тексты переносятся по словам, нижние кнопки адаптируются к узким экранам. Проверка `e2e/site.mjs` дополнительно имитирует Android WebView и проверяет кнопку «Профиль» справа. Обычный браузер и Android остаются разными представлениями.

## Сайт и приложение — два разных интерфейса

**Веб-сайт:** откройте стенд в обычном браузере на компьютере. При ширине окна больше 800 пикселей вы увидите широкий сайт с крупным первым экраном, горизонтальным меню и карточками услуг в несколько колонок. На планшете и телефоне сайт адаптируется под меньшую ширину, но остаётся веб-сайтом.

**Android-приложение:** WebView, открытое из оболочки `android/`, использует компактный интерфейс приложения с нижней навигацией. Сайт в обычном браузере не должен показывать эту нижнюю панель.

**Проверка:** GitHub Actions запускает оба сценария: `e2e/site.mjs` для сайта (390, 900 и 1440 пикселей) и `e2e/flow.mjs` для пользовательских операций. Внизу сайта указан номер собранной версии; проверьте его, если видите старый интерфейс.

## Запуск сервера

```bash
npm install
createdb traksos
DATABASE_URL=postgres://postgres@127.0.0.1:5432/traksos ADMIN_PHONES=+79990000001 npm run dev
```

Миграции применяются сами при старте. Веб-приложение: `npm run build` — сервер раздаёт его на том же адресе. Тесты: `TEST_DATABASE_URL=postgres://…/traksos_test npm test`.

Пока SMS-сервис не подключён (`SMS_PROVIDER=log`), код входа пишется в лог и возвращается в ответе `/api/auth/code` как `devCode` — только вне production.

## Переменные окружения

| Переменная | Зачем | Когда нужна |
| --- | --- | --- |
| `DATABASE_URL` | PostgreSQL | всегда |
| `APP_SECRET` | хэши кодов и токенов | production |
| `ADMIN_PHONES` | номера админов через запятую | всегда |
| `PUBLIC_URL`, `CORS_ORIGINS` | адрес сайта | production |
| `SMS_PROVIDER=smsru`, `SMSRU_API_ID` | коды входа по SMS | перед запуском |
| `PUSH_PROVIDER=rustore`, `RUSTORE_PROJECT_ID`, `RUSTORE_SERVICE_TOKEN` | вызов мастеру как звонок | Android-приложение |
| `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_*` | оплата на сайте | после юриста и бухгалтера |

## Главное в логике

- **Вход** — номер телефона и код. Роли: клиент (владелец), водитель, мастер, эвакуаторщик, сервис, модератор, админ. Водитель привязан к машине владельца.
- **Заявка и SOS** — цена считается сразу: выезд по зоне (КАД, до 30 км, Гатчина … Усть-Луга), за КАД км × 1,5 × ставка, ночью ×1,5, совместный выезд дальше 30 км — 70%.
- **Вызов и торги** — сначала заявка 30 секунд звонит приоритетным (вы с отцом; выключается в админке «Распределение»), потом уходит на торги всем подходящим рядом как звонок. Исполнитель откликается по обычной цене или своей — от 85% до 130%. Клиент видит один список с сортировками «Рекомендуем / Дешевле / Быстрее / Ближе»; в «Рекомендуем» цена весит 15%, рейтинг 35%, так что дешевизной в топ не выйти. SOS: через 90 секунд лучший назначается сам. Эвакуатор — так же, с подачей «сборы + дорога».
- **Статусы** — ищем → принял → в пути → на месте → работает → ждёт подтверждения суммы → готово; отмена и «никто не взял».
- **Сумма** — мастер называет работу, клиент подтверждает или спорит. Выезд зафиксирован при принятии.
- **Чат** — один на заявку; номера телефонов скрываются, «напрямую» и т. п. уходят модератору.
- **Отзывы** — взаимные; вес = (рейтинг автора − 3) / 2 в пределах 0,1–1, у новичка 0,3.
- **Оплата по агентской схеме** — `server/src/payments/`. Наличные работают сразу (долг мастера по сбору и вознаграждению ведётся в учёте). Безнал (СБП/карта с заморозкой выезда) и счета компаниям написаны, но выключены: включаются в настройках площадки `PUT /api/admin/settings/payments {"online": true}`. Платёжный сервис подключается через интерфейс `PaymentProvider`; есть тестовый и заготовка ЮKassa.
- **Оферты** — версии, согласия, уведомление исполнителей о новых условиях не позже чем за 15 дней (289-ФЗ).

Все суммы в API — в копейках.

## Android-приложение (RuStore)

`android/` — оболочка на Kotlin: сайт в WebView, пуши RuStore, вызов на весь экран поверх блокировки с кнопками «Беру» / «Отклонить» и звонком 30 секунд. Собирается в GitHub Actions (workflow «Android»), APK — в артефактах сборки.

Что задать в репозитории (Settings → Secrets and variables → Actions):

| Где | Имя | Что |
| --- | --- | --- |
| Variables | `APP_URL` | адрес сайта, например `https://traksos.ru` |
| Variables | `RUSTORE_PROJECT_ID` | ID проекта Push в консоли RuStore |
| Secrets | `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` | ключ подписи для RuStore (имя ключа `traksos`) |

Без ключа собирается отладочный APK для проверки на своём телефоне.

## Запуск на сервере

Нужен VPS в России (Timeweb Cloud, Selectel, Yandex Cloud), 2 ГБ памяти, Docker. Образ собирается сам при каждом изменении: `ghcr.io/shipaka/traksos`.

```bash
git clone https://github.com/shipaka/traksos && cd traksos/deploy
cp .env.example .env   # заполнить домен, пароли, номера админов
docker compose up -d
```

Caddy сам получит HTTPS-сертификат, база копируется раз в сутки в `deploy/backups`.
