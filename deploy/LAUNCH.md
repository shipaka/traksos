# Первый публичный стенд TrackSOS — Санкт-Петербург и Ленинградская область

Дата подготовки: 12.11.2026. Приоритет — доступный сайт по `https://traksos.ru` для переговоров с партнёрами; это не разрешение принимать платежи или документы реальных пользователей до проверки требований.

## Покупка VPS (с владельцем)
Выбрать российский VPS: Ubuntu 24.04 LTS, 2 vCPU / 4 ГБ / 50 ГБ NVMe или лучше, обязательно публичный IPv4. Например, Timeweb Cloud Cloud-50 в регионе Санкт-Петербург или Москва. Проверить итоговую цену с IPv4 и копиями, а не только цену тарифа. Открыть входящий TCP 22 (для SSH), 80 и 443 (для сайта). Нельзя публиковать в чат root-пароль, APP_SECRET или ключи сервисов.

## DNS
Домен `traksos.ru` уже принадлежит владельцу. У действующего DNS-хостера изменить A-запись `@` на публичный IPv4 VPS (удалить старые конфликтующие A-записи), по желанию `www` позже. NS-серверы указывают, **где** править DNS, а не куда хостить. Срок применения обычно 15 минут — 3 часа, иногда больше. Домен `траксос.рф` подключать вторым этапом как редирект; не задерживать главный сайт.

## Установка на чистом Ubuntu 24.04
Подключиться к VPS по SSH или через веб-консоль хостера, выполнить **на самом сервере**:

```bash
sudo apt-get update
sudo apt-get install -y git curl ca-certificates python3 openssl docker.io docker-compose-v2
sudo systemctl enable --now docker
git clone https://github.com/shipaka/traksos.git
cd traksos
sudo bash deploy/launch.sh
```

Если Docker Compose v2 отсутствует в репозиториях вашей системы, установить Docker Engine + Compose plugin по официальной инструкции https://docs.docker.com/engine/install/ubuntu/ и повторить `sudo bash deploy/launch.sh`. Скрипт попросит номер администратора в формате `+7XXXXXXXXXX`, **сгенерирует секреты на VPS** (не в чате), соберёт веб и сервер, поднимет PostgreSQL и Caddy. Существующий `deploy/.env` он не перезаписывает.

## Проверка
```bash
cd ~/traksos/deploy
sudo docker compose ps
sudo docker compose logs --tail=80 app
curl -i https://traksos.ru/api/health
```
Ожидается JSON с `ok:true` и `db:true`. Проверьте главный экран и адаптацию по HTTPS на телефоне, затем форму входа, заявку SOS и админ-раздел. **Регистрация и восстановление пароля по SMS на публичном сервере пока НЕ заработают**, если `SMS_PROVIDER=log`. Это только технодемо: после подключения SMS.ru в `deploy/.env` поменять `SMS_PROVIDER=smsru`, записать `SMSRU_API_ID` **на сервере**, перезапустить `sudo docker compose up -d app` и протестировать на собственном номере. Не помещать SMSRU_API_ID в коммиты, скриншоты или чат.

## Платежи
`PAYMENT_PROVIDER=mock` — **не принимать живые деньги**, любые пользовательские кнопки реальных оплат держать выключенными в админке. Тестовую ЮKassa можно оформить заранее для проверки `shopId` и `secretKey`, но включая её, отдельно проверить обработку уведомлений, чеки по 54-ФЗ, агентскую схему и выплаты; тестовую и реальную ЮKassa не смешивать. Пока нет подтверждения от юриста и бухгалтера, не разрешать реальные списания.

## Минимальная безопасность
- Российская локация сервера; DB-порт 5432 **не** открыт наружу; публичные только 80/443.
- Хранить `deploy/.env` как 600, не включать его в Git.
- Бэкапы `deploy/backups` на том же VPS **не заменяют внешних** резервных копий, включить их у хостера.
- До начала обработки реальных личных данных уточнить обязанности оператора по 152-ФЗ, включая уведомление Роскомнадзора и политику конфиденциальности; проверить обработку сканов документов.
- На публичной карте демо-точки подписаны как условные, без личных данных; услуги ограничены Санкт-Петербургом и Ленинградской областью.
- Для приложения указан только RuStore; ссылка на скачивание появится после публикации.

## Резервные копии и восстановление
Контейнер `backup` ежедневно создаёт атомарный PostgreSQL-архив `deploy/backups/traksos-YYYY-MM-DD.dump`. Неудачная выгрузка не заменяет вчерашний архив; каждый файл проверяется `pg_restore --list`. Локальная история хранится приблизительно две недели. Нужны **внешние** зашифрованные копии/снимки дисков у российского хостера: единственный VPS не защищает от его полного отказа.

Проверка архива на VPS (без публикации содержимого):
```bash
cd ~/traksos/deploy
sudo docker compose exec backup sh -c 'ls -lh /backups/traksos-*.dump'
sudo docker compose exec backup sh -c 'pg_restore -l "$(ls -1t /backups/traksos-*.dump | head -1)" >/dev/null && echo BACKUP_OK'
```
После первого запуска выполните пробное восстановление в отдельную тестовую БД, **не поверх работающей базы**:
```bash
sudo docker compose exec db createdb -U traksos traksos_restore_test
sudo docker compose exec backup sh -c 'pg_restore -h db -U traksos -d traksos_restore_test --no-owner --no-acl "$(ls -1t /backups/traksos-*.dump | head -1)"'
sudo docker compose exec db dropdb -U traksos traksos_restore_test
```
Если проверка или восстановление не проходят, запуск реальных данных блокируется до исправления.

## Обновление
```bash
cd ~/traksos
git pull --ff-only
cd deploy
sudo docker compose up -d --build
sudo docker compose ps
```

## Если что-то пошло не так
```bash
cd ~/traksos/deploy
sudo docker compose logs --tail=120 app
sudo docker compose logs --tail=120 caddy
sudo docker compose ps
```
Ошибка DNS/сертификата: проверить A-запись и публичные 80/443; ошибка `APP_SECRET`: проверить `deploy/.env` без отправки содержимого третьим лицам; DB не готова: `sudo docker compose logs db`. Передавать для диагностики **только текст ошибки после удаления секретов, номеров телефонов и персональных данных**.
