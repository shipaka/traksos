# TrakSOS — сборка транспорта и экосистемы: условия релиза

Кандидат: PR #152, ветка feature/release-vehicle-experience-community-20261117.
Это инструкция предрелизной проверки, а не заявление об обновлении Timeweb.

## Состав пакета

- #111: Эфир, Клуб, внутренняя инфраструктура магазина/курьера и профессиональные кейсы. Запуск магазина, реальных платежей, логистики и провайдера Автоконтинент НЕ включается автоматически.
- #151: право на закрытые ремонтные материалы только подтверждённым мастерам и СТО, с серверной проверкой; админские очереди модерации отдельны. Tow, driver, client, insurer не видят ремонтный контур.
- #143: справочник 8460 модельных семейств VehiclesDB CC BY 4.0, версионные ключи и очередь отсутствующих вариантов.
- #150: отдельные прицепы/полуприцепы, грузовые марки РФ/КНР, ограниченный перечень настоящих тяжёлых эвакуаторов; фото по лицензии, операторские руководства, книжка в гараже ПК/мобильный/Android. Проверка эвакуаторной техники выполняется также сервером.
- #152: «Опыт эксплуатации» отдельно от Эфира и ремонта: фильтры по марке/модели, темы, публикации, сохранённое, жалобы и ручная модерация, из карточки ТС. Контекст модели доходит до магазина только справочно, НЕ является VIN-подбором. Владелец дополнительно ведёт расходы по каждой машине; это не налоговый/платёжный реестр. Персональные данные включены в экспорт и удаление.

## Исключения

- Налоговые PR #124, #138, #139 не входят: владелец ещё разрабатывает модель и не давал разрешения.
- Дизайн-проекты #112/#121 и Android PIN #108 не объединять без проверки согласованного внешнего вида и безопасности.
- PR #144 КПП/GPS находится на отдельной приёмке, в этот код не влит: сначала согласие и права доступа.
- Нет подтверждённого полного VIN-подбора запчастей, OEM-копий сервисных PDF, API Автоконтинента, прав на рекламу OEM-фото. Ссылки на документы изготовителя не дают права хранить их копии.

## Стоп-условия до merge и развёртывания

1. Целевой SHA из GitHub совпадает с успешно прошедшими полными «Проверка», Android PR smoke (реальное открытие APK API 29/35), 200-users и повторным 1000-users нагрузочным тестом на интеграционной ветке. Старые зелёные workflow другой ветки недостаточны.
2. Все tests владельца, водителя, tow, master, STO, администратора, модератора, новых публикаций, модерации, финансов гаража, карточек моделей и ролей проходят. Подтвердить границы доступа прямыми запросами, не только видимостью кнопок.
3. Без регрессий утверждённые splash, логотип, фура, кабинетные стили, кнопки Войти/Назад, статусные кнопки, OTP, APK, мобильные экраны 320/390 и desktop 1440. Смотреть скриншоты CI и выполнить физический телефонный тест.
4. Фото имеют автора, страницу и лицензию с указанием, какая модель/семейство изображена; изображения без подтверждения заменяются fallback. Не выдавать семейство за точную комплектацию и не копировать защищённые OEM-фото.
5. Магазин закрыт до отдельного явного решения, даже при готовой кодовой инфраструктуре. Ни боевые SMS, ни Push, ни платежи не направлять из sandbox.

## Timeweb: только после одобренного merge в main

A. Сначала резервная внешняя копия и проверенный тестовый restore в отдельной базе, затем осмотр рабочих контейнеров, диска, DNS, Caddy и HTTPS. Никакого удаления Docker volumes и переноса клиентов/секретов в sandbox.
B. Отдельный sandbox.traksos.ru, собственная PostgreSQL и сеть, иные секреты; SMS_PROVIDER=log, PUSH_PROVIDER=log, PAYMENT_PROVIDER=mock. Проверить health с sandbox=true и buildRevision кандидата, а также отсутствие доступа к рабочей БД.
C. Проверить рабочий Git main и чистый каталог; git pull --ff-only origin main. После последнего зелёного CI точного SHA выполнить bash deploy/verify-shop-closed.sh и bash deploy/update-site.sh (скрипт создаёт и валидирует custom pg_dump, проверяет sandbox и обновляет только app).
D. После развертывания повторить role smoke, гараж/руководства/опыт/расходы, URL и фото; подтвердить health и buildRevision на обоих доменах, SMS.ru на реальном номере и RuStore Push на устройстве. Debug APK не считать релизным.
E. При ошибке остановить процедуру; сохранённый дамп не означает безопасный автоматический откат, поскольку миграции могут несовместимо изменить схему. Не делать git reset --hard, down -v, pg_restore --clean.

До этих проверок статус — только черновик GitHub, production не обновлён.
