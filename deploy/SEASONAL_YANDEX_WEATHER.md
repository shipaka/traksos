# TrakSOS — сезонная Android-заставка + фактическая погода Яндекса

## Что включено в код

- Четыре локальные фотосцены **с одной Scania R520**: весенняя мокрая трасса/оттепель, летний сухой асфальт, осенние мокрые листья и туман, зимняя снежная колея.
- Календарный сезон выбирается мгновенно по местной дате Android. Запуск без сети работает, загрузка WebView/звонки/SOS не задерживаются.
- Android запрашивает **только** HTTPS `GET /api/public/weather` по конфигурируемому адресу TrakSOS. Ключ API не включён в APK/JS.
- Сервер запрашивает Яндекс Погоду только для **Санкт-Петербурга** (59.9343, 30.3351), нормализует состояние и температуру, проверяет свежесть наблюдения (до трёх часов) и кэширует результаты на 20 минут. Ошибка провайдера кэшируется 5 минут; запросы объединяются.
- Android использует только фактическое наблюдение не старше **90 минут**. Отображает город, температуру и источник «Яндекс Погода»; погодные частицы меняются соответственно: ясное небо, облачность/дымка, дождь/гроза или снег.
- Если ключ отсутствует, сервер не отвечает, наблюдение устарело или Интернет недоступен, экран показывает **«сезонный фон»**, не выдуманную температуру или текущую погоду.
- Никакой геолокации телефона для этой заставки не запрашивается. Санкт-Петербург — стартовый регион проекта; это не погода пользователя при нахождении в другом городе.

## Подключение в кабинете Яндекс Погоды

1. Откройте [API Яндекс Погоды](https://yandex.ru/dev/weather/) и получите API-ключ для подходящего тарифа, разрешающего использование `/v2/informers`. Не путать тарифы `v2/informers` и `v2/forecast`: при несовместимом тарифе будет HTTP 403.
2. Ознакомьтесь с действующими правилами атрибуции Яндекс Погоды для публичного показа. В интерфейсе указано «Яндекс Погода».
3. **Только в защищённой консоли VPS**, внутри существующего `/root/traksos/deploy/.env`, добавьте `YANDEX_WEATHER_API_KEY=<ваш ключ>` и убедитесь, что права `deploy/.env` равны `600`. Нельзя передавать ключ в чат, GitHub, Android BuildConfig или скриншоты.
4. Сначала объедините этот PR с проверенным релизным кодом и получите **зелёные веб- и Android-сборки на том же SHA**. Это не основание обходить остальные release gates.
5. На действующем Timeweb VPS сначала выполните безопасные предрелизные проверки из [SERVER_UPDATE_NEXT_CHAT.md](SERVER_UPDATE_NEXT_CHAT.md), подтвердите рабочий `main`, сохранность базы и закрытый магазин. Запускайте только штатное обновление после резервного копирования.
6. Проверьте `curl --fail --silent https://traksos.ru/api/public/weather`; ожидается JSON с `source:yandex`, `location:Санкт-Петербург`, `condition`, `temperatureC`, `observedAt`, `attribution`. **Значения должны происходить из API, не из тестов.** Без ключа ожидается `503 {"available":false}`.
7. Установите новую **подписанную тем же ключом** APK. Старый debug APK может не обновиться поверх подписанного релиза. Проверьте заставку на физическом Android со связью и без неё; заставка не должна задерживать вход.
8. Перед RuStore ещё отдельно проверьте app lock, пуши/звонок мастеру на заблокированном экране и размер APK.

## Контрольное окно релиза

- `git status --short`, `git rev-parse HEAD` и сравнение с GitHub `main`.
- `bash deploy/verify-shop-closed.sh` **до и после** обновления.
- Проверенный архив PostgreSQL и внешняя копия; не делать `docker compose down -v`.
- `bash deploy/doctor.sh` и `curl https://traksos.ru/api/health`.
- `GET /api/public/weather` — реальная погода только если Яндекс-ключ настроен, иначе штатный сезонный fallback.
- Никаких платёжных или SQL-изменений ради заставки.

Исходная документация API: [официальный формат GET /v2/informers](https://yandex.ru/dev/weather/doc/ru/concepts/forecast-info).
