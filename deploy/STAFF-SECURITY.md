# TrakSOS — защищённые служебные аккаунты

Этот релиз НЕ публикует номера телефонов в GitHub. Все реальные номера вводятся только в приватный `deploy/.env` на VPS.

## Фиксированные роли

- Единственный администратор: `admin` + `master`, только `ADMIN_PHONES` (ровно один номер).
- Помощник: `moderator` + `master`, только `MODERATOR_PHONES` (отдельный номер).
- `RECOVERY_CONTACT_PHONE` — исключительно закрытый резервный контакт, **не второй администратор, не способ входа или автоматический сброс пароля**.
- В production регистрация с SMS и паролем создаёт только заявленную обычную категорию, не добавляет служебные роли.
- Сброс пароля по SMS для служебных аккаунтов запрещён из-за риска перевыпуска SIM.
- При каждом входе и запросе сессии сравниваются служебная роль и точный разрешённый номер.
- После смены ролей все старые сеансы изменённого пользователя прекращаются.

## Порядок безопасной активации на VPS

1. Убедиться, что есть свежая рабочая резервная копия и доступ в VPS через отдельный защищённый SSH.
2. Получить последнюю проверенную версию, затем запустить `bash deploy/configure-staff.sh`. Ввести три номера **скрыто**, без записи в Git, переписку и shell history.
3. Выполнить `bash deploy/update-site.sh`. Этот шаг пересобирает приложение с закрытыми настройками и предварительной копией БД. Если текущие аккаунты уже существовали — предварительно сверить их роли в закрытом операторском режиме.
4. Основной владелец регистрируется как **мастер** и подтверждает SMS, устанавливает уникальный пароль (от 10 символов). Администратора сама регистрация НЕ выдаёт.
5. Проверить, что зарегистрировался именно владелец номера (а не постороннее лицо с перевыпущенной SIM). Запустить `bash deploy/activate-primary-admin.sh`. Ввести пароль, установленный на сайте. Программа проверяет точный номер, пароль, отсутствие чужого администратора и отзывает старые сессии.
6. Владелец входит повторно и проверяет `Администратор ↔ Выездной мастер` и быструю очередь модерации.
7. Отец регистрируется на своём номере как мастер. Владелец, после независимого подтверждения личности, через управление ролями назначает **master + moderator**. API допускает модератора только для номера в `MODERATOR_PHONES`.
8. Проверить, что модератор не видит статистику, финансы и настройки ни в UI, ни при обращении к API. Второго администратора не добавлять.

## Важные ограничения

- Вход всё ещё основан на пароле и токене сессии; полноценная двухфакторная авторизация (например, TOTP/ключ безопасности) пока не внедрена. Нельзя утверждать абсолютную защиту от взлома.
- Для персонала восстановление пароля **не выполняется только по SMS**. До готовности отдельного защищённого восстановления требуется вмешательство владельца VPS; резервный номер сам по себе ничего не разблокирует.
- Не использовать обычную регистрацию владельца автопарка для административного аккаунта.
- Не менять список телефонов без проверки существующих аккаунтов: несовпадение закрывает привилегированный вход. Развёртывание делается только с доступом к VPS и проверенной резервной копией.
