# TrackSOS — безопасный контроль сервера из GitHub

Этот PR добавляет **только чтение** состояния VPS. Он не обновляет приложение, не меняет данные, не перезапускает Docker. Для автоматического обновления песочницы будет отдельное решение после успешной проверки доступа и резервных копий.

## 1. Первый запуск без SSH

После ревью, успешного CI и включения PR в main откройте Actions → «TrackSOS — проверка сервера и песочницы» → Run workflow, оставив include_server выключенным. GitHub проверит HTTPS адреса traksos.ru и sandbox.traksos.ru. Журналы доступны в Actions.

## 2. Однократная установка ограниченного SSH-доступа на VPS

**Не копируйте секреты в чат или в issue/PR! Не загружайте приватные ключи в репозиторий.**

После включения PR в main и проверки изменений / состояния Git на VPS, из доверенного терминала администратора выполните:

~~~sh
cd /root/traksos
git status --short
git branch --show-current
git pull --ff-only origin main
bash deploy/automation/install-monitor.sh
~~~

ОСТАНОВИТЕСЬ, если есть локальные изменения, git не на main, CI не прошёл или команда выдаёт ошибку. Нельзя делать git reset --hard. Скрипт рассчитан на Ubuntu VPS под root, не меняет Docker, сайт или базы данных. Он устанавливает только root-owned фиксированную диагностику, отдельного пользователя traksos-monitor, принудительную SSH-команду и отдельную пару ключей. Приватный ключ остаётся только в /root/.ssh/traksos-monitor-actions — GitHub его не получает автоматически.

## 3. Настройка секретов GitHub

В репозитории откройте Settings → Secrets and variables → Actions → New repository secret. Создайте следующие четыре переменные/секрета:

- TRAKSOS_MONITOR_HOST: SSH IP/hostname VPS, который уже использует Termius.
- TRAKSOS_MONITOR_PORT: SSH port, как в Termius. Если не указан, используется 22.
- TRAKSOS_MONITOR_PRIVATE_KEY: полное содержимое файла /root/.ssh/traksos-monitor-actions. Копировать **только прямо в закрытое поле GitHub Secret**; не присылать сюда и не делать скриншот. Это отдельный ограниченный ключ, НЕ root-пароль и НЕ GitHub PAT. Хранить строго конфиденциально, при утечке немедленно отозвать.
- TRAKSOS_MONITOR_KNOWN_HOSTS: проверенная строка SSH host key сервера, соответствующая тому же SSH host/port. Доверенный ключ есть на сервере в /etc/ssh/ssh_host_ed25519_key.pub (если SSH служба использует ED25519). При нестандартном SSH порте формат адресной части в known_hosts: [host]:port. Подлинность и фактически активный ключ проверить из доверенной консоли VPS.

Скрипт установки выводит публичный отпечаток серверного ED25519 ключа; приватный ключ хоста никогда не копировать.

## 4. Проверка подключения

Только после настройки четырёх secrets запустить workflow из main с include_server включённым. В журнале ожидаются безопасные статусы известных Docker контейнеров и сравнение sandbox/prod сетей. Проверка не выводит содержимое .env, базы, docker inspect .Config.Env и сырые логи.

**Ограничения:** traksos-monitor не включается в группы docker/sudo. Его SSH ключ принудительно выполняет единственный root-owned диагностический скрипт через точечное sudoers правило. Это важно, потому что доступ к Docker socket равнозначен root. Для дальнейшего обновления песочницы потребуются другие ограниченные операции, проверка миграций, back-up и отдельные защиты.

Никаких docker compose down -v, docker volume rm, автоматического pg_restore или переключения production на latest. Локальная проверка наличия бэкапа не заменяет тест восстановления.

## 5. Автоматическая диагностика без команд на VPS

После успешного подключения четырёх GitHub Secrets workflow `.github/workflows/observe-sandbox.yml` запускается по расписанию **4 раза в сутки**: 03:23, 09:23, 15:23 и 21:23 UTC (06:23, 12:23, 18:23 и 00:23 по Москве). GitHub может задержать расписание из-за очереди. Проверяются HTTPS обоих доменов и те же ограниченные SSH-проверки Docker, которые прошли вручную.

Ручной запуск остаётся доступен: с `include_server: false` проверяется только HTTPS, с `include_server: true` — также VPS. **Расписание всегда включает VPS**, отдельный запуск пользователю не нужен.

Результаты доступны в Actions → «TrackSOS — проверка сервера и песочницы». Ошибка помечает запуск красным, но GitHub Actions сам по себе **не гарантирует push/email-уведомления**: они зависят от настроек уведомлений пользователя. Эта автоматизация **не обновляет** ни песочницу, ни production, не изменяет Docker, данные или конфигурацию сервера. Для выкладки релиза необходим отдельный ключ и отдельные строго ограниченные права; расширять SSH-права `traksos-monitor` нельзя.
