## Роли и функциональность

- Владелец автопарка, водитель, мастер, эвакуаторщик, СТО, страховой партнёр, оператор техосмотра, модератор, администратор. Гибрид «мастер+СТО» имеет два отдельных режима; гидравлика присутствует в специальностях выезда/СТО.
- Регистрация через SMS только при создании/восстановлении; обычный вход по паролю, Android PIN/биометрия. Партнёры через «Хотим работать», клиенты через обычную регистрацию. Ролевые полномочия определяет сервер.
- Заявка: реальные статусы, последовательность выехал → на месте → завершено; чат/история, мультизаявка, запрет молчаливого согласия, споры и безопасное завершение при недоступности клиента. Ничего не помечать принятым без сквозного теста и прав доступа.
- Нужны связь через скрытые номера с записью по заявке и ТехБаза с ролевым доступом; наличие текстов не доказывает работу операторских интеграций.
- Магазин не открывать публично до отдельного подтверждения. Подбор по VIN/артикулу/названию/категориям, применяемость, аналоги, история покупок — целевая логика, а не повод продавать несуществующие товары.
- Обучение и подсказки публикуются синхронно с тем же SHA, что изменяет реальные роли, цены, маршруты и API.

## Деньги — только последние решения

- Клиент: 5% сверх цены; исполнитель: 5% внутри согласованной цены, разбивка клиентского сбора не доступна исполнителю. СТО: два самостоятельных потолка по 5 000 ₽ с каждой стороны за один счёт. Правила прочих услуг не расширять молча по аналогии.
- Клиентский реферал: 10% фактически полученного сервисного сбора TrakSOS в течение 180 дней; списание клиентом баллов не более 10% стоимости заказа и размера собственного сбора; без двойных начислений. Комиссия исполнителя может временно меняться только явно утверждённой акцией, зафиксированной у конкретной заявки.
- **Наличные для НОВЫХ заявок исключены.** Старые cash-ledger и суммы по прежним заказам сохраняются исключительно для правильного учёта, возвратов и аудита. Продукт не должен их предлагать в регистрациях, заказах, обучении или офертах.
- **ЮKassa исключена из действующего провайдера.** Точка выбрана для агентских B2B-счетов, но нынешний код Точки — только создание/учёт документов под выключенным флагом. Реальные зачисления, эквайринг, чеки, сверка и выплаты НЕ подключены; mock не означает полученные деньги.
- Страхование — агентская/брокерская заявка, варианты компаний, отдельная прозрачная комиссия платформы в согласованном сценарии; нельзя выдавать себя за страховую организацию или фиксировать оплату без подтверждения внешнего оператора.

## Закрытие пути тестовых платежей

Даже администратор не может включить онлайн-оплату/инвойсные платежи, пока текущий сервер работает с mock-провайдером. Настройки, сохранённые прежней БД, принудительно маскируются, а сервер отклоняет новые запросы. Пробные сделки разрешены только в отдельной non-production фикстуре. API Точки по документам не заменяет банковское подтверждение. Пользователю честно сообщается, что платные заказы временно недоступны до подключения банка.


**Отдельный демонстрационный контур:** только при `SANDBOX_INSTANCE=true` вместе с `TRAKSOS_SANDBOX_MOCK_CHECKOUT=true`, `PAYMENT_PROVIDER=mock`, `SMS_PROVIDER=log`, `PUSH_PROVIDER=log` и отдельной sandbox-БД тестовым пользователям разрешена имитация онлайн-оплаты и счёта. Это не банковское поступление, не меняет рабочий сайт и не даёт право публиковать платные заказы как действующие. Наличные и открытие магазина остаются запрещены и в sandbox.
