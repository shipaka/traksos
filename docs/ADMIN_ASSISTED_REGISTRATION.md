# Администратор: регистрация по номеру и эскалация разработчику

**Статус:** код ручной регистрации объединён в `main` (PR #97). Для работы на сайте требуется успешное обновление VPS с проверкой миграций и SMS.  
**Назначение:** отдельный управляемый администратором путь для регистрации людей (например, членов семьи или партнёров), без общего выбора категории пользователем.

## Что делает администратор

1. Открывает «Администратор → Регистрация и доступы».
2. Вводит номер, необязательное имя, выбирает одну или совместимые роли и обязательную причину. Нажимает «Создать аккаунт».
3. Если номер свободен, в БД появляется запись без пароля и без сессий. Предусмотрены роли клиент, водитель, мастер, эвакуатор, СТО, страховой партнёр, оператор техосмотра. Совместимость проверяется на сервере. Роли админа/модератора через этот инструмент выдавать **запрещено**.
4. Передаёт пользователю инструкцию: `#/activate` → телефон → SMS-код → **самостоятельная** установка пароля. Без владения номером войти нельзя; администратор не видит код и не устанавливает пароль.
5. Если номер уже зарегистрирован, новая запись не создаётся. Изменять его права нужно через существующую карточку пользователя с аудитом, не меняя чужие credentials.
6. В том же разделе можно создать **внутреннее обращение для разработчиков без входа в карточку пользователя**: номер или описание проблемы, категория, комментарий. Обращения доступны администраторам в очереди, их можно копировать для передачи в закрытый рабочий канал.

## Доставка разработчику

Обращение всегда сохраняется в `admin_developer_reports` и доступно только из административного кабинета. После миграции `113_developer_report_delivery.sql` сервер может автоматически отправлять в **закрытый HTTPS-webhook** минимальное уведомление (UUID заявки, категория, дата, ссылка на админку). Номер телефона, ФИО и описание ошибки не передаются.

Для этого оператор VPS самостоятельно задаёт **оба** приватных параметра `DEVELOPER_REPORT_WEBHOOK_URL` и `DEVELOPER_REPORT_WEBHOOK_SECRET` (не менее 20 символов) в `deploy/.env`. Подключение не происходит само по себе; без указанного закрытого канала обращения остаются в админке, а интерфейс честно показывает «Канал не подключён».

При ошибках доставки сервер сохраняет число попыток и повторяет отправку с возрастающим интервалом, до часа между попытками. После успешного ответа 2xx сохраняется `delivery_sent_at`; повторная отправка принятого обращения не выполняется. После сетевого сбоя возможен повтор с тем же `reportId` и заголовком `idempotency-key`, поэтому получатель должен устранять дубликаты.

Настройка закрытого webhook **не означает автоматической публикации в GitHub, email или мессенджере**. Требуется приватный получатель, который примет уведомление; публичный репозиторий недопустим для персональных данных. Внутреннее закрытие обращения и его доставка — независимые состояния.

## Безопасность и эксплуатация

- Все новые методы доступны **только** аккаунту с ролью `admin`, проверяемой сервером.
- Основной админ, модераторы, резервный номер восстановления и закреплённый первичный страховой номер не создаются этим путём.
- Права не обходят проверку и одобрение профиля исполнителя, документы, договоры и оферты.
- Нет принудительного входа от имени пользователя, передачи его пароля или авторизации без SMS.
- Записываются журнал действий, причина регистрации и отдельный журнал обращения разработчику.
- Новый пользователь получает свои роли только после проверки SMS и установки пароля.
- Все изменения интерфейса изолированы в существующей административной навигации; основной утверждённый дизайн и клиентские экраны не меняются, кроме добровольно открываемой формы активации.
