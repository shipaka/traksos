# TrackSOS — этап 3: сверка банковских операций (PR #139)

ВНИМАНИЕ. Это внутренний инструмент администраторов, а не банковский платёжный API, декларация или доказательство банка. Ручной нормализованный CSV имеет статус manual_unverified. Он не создаёт поступления и выплаты, не определяет налоговую базу и не подтверждает юридически совершение платежа. Для сверки денег обязателен отдельно загруженный и проверенный оригинал payment_proof.

## Почему одно финансовое ядро

PR #139 уже связан с настоящими shop_orders, приватной первичкой, API и админским экраном. Параллельный PR #138 содержит другую, не подключённую к кабинету модель shop_agent_ledger_*. Не сливать оба в main: сначала согласовать единую каноническую модель и перенос нужных механизмов, сохранив историю.

## Загрузка строго нормализованного CSV

Максимум 450 КБ и 1000 строк; кодировка UTF-8; точный заголовок:

    transaction_ref;occurred_at;direction;amount_kopecks;note

Пример:

    BANK-A-001;2026-12-01T10:00:00Z;in;1365000;"Оплата клиента; заказ 1"
    BANK-A-002;2026-12-01T12:00:00Z;out;1000000;Оплата поставщику

transaction_ref — уникальный точный ID операции для конкретного accountRef. occurred_at — ISO-8601 с Z или явным смещением. direction = in либо out. amount_kopecks — положительная целочисленная сумма в копейках. note — описание до 300 символов. Кавычки и разделитель ; допускаются по правилам CSV в одной физической строке. Не существует универсального импортера форматов всех банков: сначала нужно сохранить оригинал банка, а затем подготовить этот нормализованный формат без изменения сумм, дат и ID.

## Хранение и защита

Миграция 118_shop_agency_bank_reconciliation.sql создаёт четыре таблицы: shop_agency_bank_statements с неизменяемыми байтами CSV, SHA-256, банком, accountRef, автором; shop_agency_bank_rows с уникальной парой (account_ref, transaction_ref); shop_agency_bank_matches для истории сопоставлений; shop_agency_bank_match_retractions для документированного отзыва ошибочной связи.

Все четыре защищены SQL-триггерами от UPDATE и DELETE. Если один и тот же файл импортируется повторно с теми же параметрами, вернётся прежний ID. Повтор с иными метаданными — конфликт 409. Повтор банковского transaction_ref в другом CSV по тому же accountRef — 409 с откатом всего импорта. Ошибочная связь не редактируется: отзыв создаёт новую неизменяемую запись с причиной и позволяет повторное сопоставление. Сопоставление и отзыв повышают версию доказательств агентского кейса; прежнее утверждение может стать неактуальным.

## Проверка совпадения

Один банковский ряд сопоставляется только с одним активным денежным событием и наоборот. Сверяются точный номер source_ref/transaction_ref, сумма копеек, направление (приход либо расход), расхождение дат не более 7 суток, наличие проверенного payment_proof на эту операцию и отсутствие другого активного соответствия.

Приход: customer_receipt, supplier_refund, supplier_payment_reversal.
Расход: supplier_payment, customer_refund, customer_receipt_reversal.
handover и agent_report сопоставлять нельзя. Положительный результат не инициирует новые денежные операции.

## Приватный API

Все маршруты доступны только роли admin:
- POST /api/admin/agency/bank/statements
- GET /api/admin/agency/bank/statements
- GET /api/admin/agency/bank/statements/:id/rows
- GET /api/admin/agency/cases/:id/bank
- POST /api/admin/agency/bank/matches
- POST /api/admin/agency/bank/matches/:id/retract

Партнёры и клиенты не видят эти данные. Исходный CSV защищён в PostgreSQL, а не отдается публичным URL. До работы с реальными выписками нужны правила хранения данных, разграничение прав, защищённые бэкапы и организационные требования 152-ФЗ.

## Приёмка

server/test/shopAgencyBank.test.ts проверяет парсер 1000 строк, ручной импорт, контроль SHA и повторов между выписками, роли, запрет прямого SQL-изменения, проверку исходного платёжного оригинала, направление/сумму, отзыв и повторную связку, отсутствие автоплатежей.

**1000 строк — не 1000 одновременных пользователей.** Такой нагрузочный тест проводится отдельно на полностью изолированной тестовой PostgreSQL. PR остаётся draft до выбора единой модели, финансово-юридического утверждения, подключений поставщика/банка и приёмки песочницы.
