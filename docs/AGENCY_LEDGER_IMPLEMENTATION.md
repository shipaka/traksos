# TrackSOS · агентские закупки — доказательный реестр (реализация)

**Статус:** отдельный закрытый администраторский модуль. Не включает магазин, API «Автоконтинента», оплату/возвраты, налоговую декларацию или автоматическое признание дохода.

## Границы

- Миграция `116_shop_agency_evidence.sql` создаёт только новые таблицы `shop_agency_*`; действующий `shop_orders`, `payments`, клиентский каталог, мобильные рабочие кабинеты и договоры не меняются.
- API и экран **Администратор → Финансы и документы → Агентские закупки** доступны строго роли `admin`. Закупочные суммы, сканы и служебные ревью не попадают в публичные API, кэш APK, кабинеты клиента, мастера или модератора.
- Записи привязываются к существующему заказу магазина и **конкретной позиции в неизменяемом снимке `items`**. Дубли одного заказа/позиции запрещены.
- Операция различает `client_purchase_agent`, `supplier_sales_agent`, `own_inventory_sale`. Клиентская агентская схема требует существующего поручения, времени акцепта, версий оферты/тарифа и точного совпадения суммы с ценой позиции заказа.
- Первичные документы — файл PDF/JPEG/PNG не более 450 КБ, SHA-256, реквизиты, дата, сумма/НДС/количество. При загрузке статус **manual_unverified**; ручное подтверждение записывается отдельно, никогда не приписывается API поставщика.
- Один документ распределяется по нескольким операциям через ключи строк. Общая сумма/количество/НДС распределений не могут превышать оригинал. Полные и частичные поставки — отдельные документы и строки.
- Приходы, оплаты, возвраты и сторно добавляются как **новые неизменяемые события** с ключом идемпотентности и датой. При несовпадении данных под старым ключом — `409`.
- Сверка показывает недостающие документы, недоплаты, расхождения закупки и поручения, НДС, переизбыточные перечисления. Комплект можно отметить проверенным только после устранения проблем. Новые события меняют `evidence_version` и автоматически делают прежнюю отметку неактуальной.
- Отчёт по датам использует гражданские сутки **Europe/Moscow**, недельные периоды строятся из пользовательских дат. У денежных сумм в отчёте дата — **фактическое событие**; текущие документы и согласованная стоимость отображаются по связанной операции. Группировка по компаниям/ИНН.
- CSV экранирует формулы электронных таблиц и содержит статус первички, различает фактическую и подтверждённую стоимость. Не подменяет бухгалтерский пакет.

## API (все маршруты: только админ)

| Метод | Маршрут | Результат |
| --- | --- | --- |
| POST | `/api/admin/agency/cases` | Привязка операции к позиции реального заказа |
| GET | `/api/admin/agency/cases/:id` | Полная цепочка доказательств, событий, ревью и расхождений |
| POST | `/api/admin/agency/documents` | Загрузка оригинала, SHA-256, защита от дублей |
| POST | `/api/admin/agency/documents/:id/verify` | Ручная проверка файла с основанием |
| GET | `/api/admin/agency/documents/:id/file` | Оригинал, приватный no-store ответ |
| POST | `/api/admin/agency/cases/:id/allocations` | Распределение документа по позиции |
| POST | `/api/admin/agency/cases/:id/events` | Идемпотентное событие денег/передачи |
| POST | `/api/admin/agency/cases/:id/review` | Переход в verified / accountant_approved при полной сверке |
| GET | `/api/admin/agency/report?from=YYYY-MM-DD&to=YYYY-MM-DD` | Сводка, юрлица, операции, проблемы |
| GET | `/api/admin/agency/report.csv?from=...&to=...` | CSV для дальнейшего учёта |

Период ограничен 366 днями; чтобы не получить **молча урезанные** итоги, при более чем 2000 операциях сервер отказывает в формировании большого отчёта и требует меньший диапазон.

## Пример проверки чисел

- Согласованная покупателем позиция: **13 650 ₽** (1 365 000 коп.).
- Подтверждение закупки: **10 000 ₽** (1 000 000 коп.), входной НДС отдельно по оригиналу.
- Агентская услуга по подписанной версии тарифа: **3 000 ₽**.
- Дополнительный сервисный сбор: **650 ₽**, отдельно от ставки НДС.
- Потенциальное вознаграждение агента по договорной арифметике: **3 650 ₽**.
- Это **не** автоматическая налоговая база. База по УСН/НДС, период признания, вычеты и бухгалтерская проводка не выводятся без правовой квалификации и подтверждения бухгалтером.

## Что остаётся вне данного блока

1. Финальное юридическое заключение по модели агента клиента/агента поставщика/перепродавца, агентские оферты и подписанные поручения.
2. Подтверждённый API и права доступа «Автоконтинента»; адаптер источника и автозагрузка настоящих УПД.
3. Автоматическая связка со сверенным платёжным провайдером/банком и ЭДО, электронные подписи, безопасный архивный экспорт PDF/ZIP, интеграция с 1С, формальная КУДиР/налоговая декларация.
4. Связь с действующим приложением магазина: по решению владельца и лишь после проверки договорной схемы. По умолчанию `settings.shop.enabled` **не меняется**.
5. Доставка оригиналов в долговременное хранилище, стратегия хранения и резервного копирования по 152-ФЗ/налоговым срокам, масштабирование отчёта более 2000 операций.

## Приёмка

Тест `server/test/shopAgencyLedger.test.ts` проверяет обязательность поручения, запрет несогласованной разбивки, отсутствие признания без первички, границы распределения, SHA-256/идемпотентность, статусы до/после проверки, московское время событий, частичный возврат, разграничение прав, собственную перепродажу и что `taxableRevenue` остаётся `null`. Запускать один раз по завершении блока в disposable базе и затем отдельный интеграционный нагрузочный сценарий, **не в общей базе**.

ТЗ: issue #123, юридическая схема #122, документация PR #124. Ни одна отметка данного модуля сама по себе не означает «готово для ФНС».
