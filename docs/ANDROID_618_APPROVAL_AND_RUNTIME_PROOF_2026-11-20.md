# Android TrakSOS: проверяемый эталон 618.png, 20.11.2026

**Статус:** критерии приёмки, а НЕ отчёт о готовой APK. Пользователь
утвердил оригинальный экран клиента (левая половина 618.png);
эталон правого экрана мастера используется для сверки. Различия плотности
пикселей, системной строки Android и доступных API-данных допустимы, но
не произвольные замены структуры или старые макеты.

- Оригинальный файл: `618.png`, JPEG-данные 1536×1152,
  SHA256 `3cb0a44fc9d831e90ba8d7a446a4bf5602fdf4658d1c97df596232a02642d32f`.
- ПК-эталон `617.png` должен остаться неизменным.
- Оригинальная машинка TrakBot должна оставаться именно оригинальным
  дружелюбным говорящим грузовичком. Плавающий блок не перекрывает
  утверждённый мобильный экран; доступен личный чат в Меню.

## Клиент: обязательные видимые элементы в том же порядке

1. Логотип TrakSOS, уведомления, профиль, подписанный переключатель роли.
2. Текстовый заголовок «Рабочий стол» — без дополнительного баннера над плитками.
3. Четыре сервиса: **Выездной мастер** (оранжевый), Эвакуатор, СТО,
   Консультация. Все четыре имеют SVG и существующие рабочие маршруты.
4. Активная заявка: номер/статус; фото **той же марки, модели и поколения**,
   если совпадение подтверждено каталогом, либо честная заглушка;
   неисправность, адрес и маршрут; ETA только если сервер сохранил оценку
   при подборе исполнителя, с подписью, что она не является live GPS.
5. Пять шагов статуса с настоящими отметками времени — отсутствующие
   значения не выдумываются. Нажатие на фото машины открывает её историю,
   заголовок — заказ, «Чат» — настоящий диалог.
6. Назначенный мастер: реальное имя, публичный рейтинг, число отзывов
   (только если эти поля присутствуют), контакты через существующие
   разрешённые сценарии и чат; никакого выдуманного портрета и прямого
   раскрытия личного телефона.
7. Стоимость по серверу в копейках: работа+выезд, клиентский сервисный
   сбор, итог. Комиссия исполнителя **не показывается клиенту**.
8. Карточка «Моя техника» и оранжевая кнопка «Новая заявка на сервис».
9. Ровно **пять** нижних пунктов: Главная, Заявки, Эфир, Техника, Меню.
   Магазин, страхование, обучение, TrakBot, документы остаются внутри
   полноценного меню — дополнительная шестая иконка запрещена.

## Выездной мастер: обязательные элементы

1. Общие с клиентом шапка/логотип, строка «Выездной мастер» с
   реальным переключением «На линии», заголовок «Рабочий стол».
2. Три счётчика из API: число принятых сегодня заявок, рейтинг,
   данные финансового сервиса. Не подставлять «3»/«4.9» в production.
3. Текущая заявка с реальной машиной/неисправностью/адресом,
   клиентом, рабочими переходами в контакты и чат.
4. Дорожная навигация и исходная оценка времени, пять этапов и их
   серверные timestamps.
5. Строго последовательный серверный переход **Выехал → На месте →
   Начать работу → расчёт/завершение**. «Завершить» не может обойти
   обязательный следующий этап или согласование.
6. Три реальные суммы: `amount`, `commission`, `payout`; никакой
   клиентской надбавки в интерфейсе исполнителя.
7. Три дополнительных рабочих действия: **Фото** (настоящий выбор
   камеры/галереи, сжатие без EXIF, загрузка только назначенным мастером
   в действующую заявку, шифрование и галерея для участников), Отчёт
   (существующая карточка расчёта), Запчасти (магазин при разрешённом доступе).
8. Четыре нижние вкладки: Главная, Заявки, Чат, Меню.

## Реальные дополнительные разделы

Каждая роль и каждое вторичное окно должны иметь ту же палитру,
модульные карточки, не менее 44px у основных нажатий, актуальные данные,
название раздела, возврат на рабочий стол и полное ролевое меню. Обучение
обязано изменяться одновременно с маршрутами. Пользовательские настройки
уменьшения анимаций отключают эффекты. Чужие роли и данные не доступны.

## Фото грузовика: известный разрыв с картинкой

На эталоне написано **Scania R440, 2010, 4×2**, а прежний
оптимизированный локальный каталог содержит **Scania R520 (2016+)**.
Это НЕ одна модель; подменять фотографию запрещено. Для нового фото R440
4×2 найден соответствующий **CC0 1.0** оригинал на Wikimedia Commons:
`https://commons.wikimedia.org/wiki/File:SCANIA_R_440_A_4X2,_De_Koeijer.JPG`,
автор Alf van Beem, фото снято в 2014 г. (это дата фотографии, а не
точная дата выпуска ТС). До получения, проверки/оптимизации и включения
файла в локальные assets для 2010 R440 должна быть безопасная заглушка.

## Требования к реальной приёмке

1. Запустить `npm -w server run typecheck` и `npm -w web run build`;
   выполнить `node scripts/verify-approved.mjs` и весь набор тестов.
2. Запустить с изолированной PostgreSQL `server/test/orderPhotos.test.ts`:
   шифрование, чтение только участниками, запрет посторонним, дубликаты,
   закрытые заявки. Миграция должна применяться успешно.
3. Прогнать `e2e/android-apk-design-review.mjs` на **реальном React**
   при синтетических данных; подпись «debug bridge» обязательна.
4. Прогнать `e2e/android-approved-real-screens.mjs` на аутентифицированных
   локальных тестовых аккаунтах. Снять отдельные PNG клиента, мастера,
   меню, заявок, техники, финансов, профиля, чата, фото; проверить ширину
   320 и 390 CSS px, отсутствие горизонтального скролла.
5. Собрать текущий web bundle внутрь свежей Android APK, установить
   настоящую APK в эмуляторы (минимум Android API 29 и 35).
   Проверить уведомления, актуальную нижнюю навигацию, живые API
   показатели и Android-камеру, включая отказ от доступа.
6. Сверить **на том же commit SHA** кадры установленного Android с
   оригиналом 618.png и прислать владельцу КАЖДУЮ роль отдельной
   читаемой фотографией. Браузерные PNG не выдавать за эмулятор.
7. Никакой автоматической публикации на сервер или в RuStore без
   проверенного билда и согласования владельца.

**До выполнения этих пунктов нельзя говорить «пиксель-в-пиксель»,
«готовая APK» или «всё уже на сервере».**
