# TrakSOS — проверка утверждённого Android в установленном APK (20.11.2026)

## Назначение

Дизайн-обзор предназначен для проверки **настоящих React-компонентов** Android WebView, встроенных в **отладочный APK** из текущего SHA ветки `design/owner-final-pc-cabinets-20261120`. Это не новый рисунок и не отдельная HTML-заглушка. Он не заменяет проверку реальных API, серверных данных и ролей.

**Утверждение по источникам:** из оригинала `618.png` по новой последовательной приёмке окончательно утверждён **клиент/владелец автопарка**. Мастер и прочие роли сохраняют предыдущие требования, но не считаются вновь утверждёнными лишь из-за наличия в APK.

## Как проверить на телефоне

1. После запуска GitHub Actions **Android PR smoke (unsigned debug)** для нужного SHA открыть его артефакт `tracksos-pr-debug-apk` и установить `app-debug.apk`. Дождаться, когда GitHub покажет успешное завершение проверок.
2. На стартовом экране APK использовать ссылку **«Посмотреть кабинеты APK»**; если сервер недоступен — кнопку **«Проверить кабинеты Android»**. Можно также открыть `#/android-review/client` внутри самой отладочной оболочки.
3. Переключать по одному экраны **Клиент**, **Водитель**, **Мастер**, **Эвакуатор**. Изображения и основной каркас идут из тех же исходников, что действующие кабинеты. Тестовая заявка синтетическая; клики по её рабочим кнопкам намеренно заблокированы, чтобы не отправлять реальные заказы.
4. Для полного функционального теста войти в созданный **изолированный** аккаунт на соответствующем sandbox-сервере; там должны проверяться реальные статусные переходы, заявки, чаты, поиск, права и суммы. Экраны предварительного просмотра не дают обхода SMS/логина реальных аккаунтов.

## Технические предохранители

- Обзор доступен только там, где нативный мост отвечает `isPreviewBuild() === true`, то есть в отладочном APK; обычный браузер и release APK не раскрывают его.
- Android загружает локальные вложенные картинки модели `/vehicles/models/*.webp`, не смешивая марку/модель. `BundledWeb` отвергает `..`, `.` и некорректные сегменты путей.
- Веб-ресурсы встраиваются из **текущего PR**. Перед сборкой каталог `android/app/src/main/assets/www` очищается и пересоздаётся, запрещённые старые визуалы отклоняются.
- `e2e/android-apk-design-review.mjs` проверяет 320/390px, четыре роли, скриншоты, запрет API-мутаций, отказ в просмотре без debug-bridge.
- `scripts/android-pr-runtime-smoke.sh` ставит этот APK на эмуляторы Android API 29 и 35, делает снимки реальных компонентов, отвергает пустой экран и нативный crash/ANR.

## Критерий «копия в копию»

Не заявлять пиксельное соответствие, пока не получены: **1)** точный исходник утверждённого `618.png`, **2)** PNG с установленного последнего APK на согласованной геометрии и плотности, **3)** визуальная сверка и прямое подтверждение владельца по каждому экрану. `617.png` относится к ПК и отдельно не подменяет Android. Другие Android-роли могут показываться как рабочие кандидаты, но не как прошедшие утверждение.
