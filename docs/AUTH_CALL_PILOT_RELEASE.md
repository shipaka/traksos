# TrackSOS — входящий Flash Call: безопасная приёмка до включения

Срез только серверной авторизации (PR #158). Не менять пока согласованный
интерфейс регистрации или Android; не включать звонки на действующем VPS
автоматически, не менять `main` до общего релиза.

## Существующая модель

- Телефон нужен для первичной регистрации и восстановления забытого пароля.
- Обычный вход — `/api/auth/login` с паролем. Провайдер при входе не вызывается.
- Пароль аккаунта: **10–128 символов**, желательно запоминаемая длинная фраза;
  хранится сервером как `scrypt` с отдельной солью, не в открытом виде.
  Четырёхзначный номер не становится серверным паролем.
- Короткий PIN/биометрия — отдельный **локальный** Android-механизм из PR #108,
  не интегрировать его одновременно с чужим редизайном без проверки Android
  Keystore, смены аккаунта и защиты перебора.

## Реализованная проверка звонком

Провайдер SMS.ru: `POST https://sms.ru/code/call`. SMS.ru звонит **клиенту**
со случайного номера; клиент вводит четыре последние цифры номера, с которого
поступил входящий вызов. Никаких звонков со стороны клиента или платных
исходящих вызовов с его номера. Не путать с SMS.ru `/callcheck/add`
(обратный поток: абонент звонит провайдеру).

- `AUTH_VERIFICATION_CHANNEL=sms` — **по умолчанию**: существующие SMS.
- `AUTH_VERIFICATION_CHANNEL=call` — включается отдельно **после** окончания
  работы над UI, тестовых входящих звонков и одобрения владельца.
- Для реальных звонков: `SMS_PROVIDER=smsru` + **уже существующий**
  `SMSRU_API_ID` только в защищённом `deploy/.env`. Новых секретов не нужно.
- В production Flash Call не запускается без настоящего **публичного IP клиента**: проверить безопасную настройку `TRUST_PROXY` за Caddy. Вместо передачи `ip=-1` при автоматической регистрации сервер откажет до исправления прокси. В локальных тестах `-1` допускается только для синтетических случаев.
- Сервер резервирует бюджет/ограничение по номеру и IP **до** вызова провайдера.
  После успешного ответа хранит **только HMAC** четырёх цифр, не сам код,
  не номер вызова или секрет провайдера. В API возвращаются только
  `sent:true`, `channel:"call"`; **`devCode` не возвращается**.
- TTL 5 минут, один запрос на телефон в 60 секунд, максимум 8 за 24-часовые
  UTC-периоды и 15 с одного публичного IP в час; до 5 неверных попыток,
  безопасная атомарная проверка с PostgreSQL advisory lock. Отзыв прошлых
  сеансов и push-токенов при сбросе пароля.
- Если SMS.ru явно отклонил звонок: удаляется только конкретный ожидающий
  код, сохраняется израсходованный бюджет. При тайм-ауте/неполном ответе
  код остаётся недействительным, а период охлаждения сохраняется, чтобы
  не инициировать повторно тарифицируемые звонки автоматически.
- В песочнице `SANDBOX_INSTANCE=true` запросы регистраций отключены.
  При локальном тесте можно подключить синтетический provider.

## Что должно быть сделано оператором на реальном VPS

1. Сначала штатная read-only диагностика VPS, изоляция sandbox, резервный
   `pg_dump`, проверенная внешняя копия и пробное восстановление. Никогда
   не включать новую авторизацию через тестовую DB с рабочими ключами.
2. На отдельном, безопасном тестовом контуре проверить реальный звонок на
   **собственный Tele2** и получение корректных последних четырёх цифр.
   Затем — согласованные тестовые SIM МегаФон, Билайн и T-Мобайл,
   проверка недозвона, занятой линии, блокировки неизвестных номеров,
   роуминга и лимитов. Не использовать номера реальных клиентов.
3. Согласованный новый интерфейс должен объяснять **«Мы позвоним вам,
   введите 4 последние цифры номера входящего звонка»**, не говорить
   «отправили SMS», когда канал `call`. UI должен читать `channel` ответа,
   а не вычислять его самостоятельно.
4. Проверить реальный /api/auth/code только для `register` и `reset`,
   ввод 4 цифр через /api/auth/verify, невозможность повторного использования,
   лимиты и отзыв старых сессий при recovery. Проверить после смены пароля
   обычный вход без любых телефонных вызовов.
5. **Только после приёмки и согласования:** изменить `AUTH_VERIFICATION_CHANNEL`
   в рабочей конфигурации и выполнить штатное безопасное обновление
   (не `docker compose down -v`, не `git reset --hard`, не переносить
   sandbox-базу в production). Не включать автоматический fallback на платные
   SMS или отдельный провайдер без отдельного решения.

Источник API: https://sms.ru/docs/api/api_group_call/code_call
(13.05.2026). В документации указан ориентир **0,40 ₽/звонок по РФ**,
реальный тариф и доставка зависят от договора и оператора.
Подключение буквенных SMS-отправителей Tele2/СберМобайл и других операторов
**не доказывает** готовность входящего Flash Call для всех сетей.

## Не включено в этот backend PR

- UI регистрации/восстановления, Android PIN/биометрия, push,
  настоящие платёжные операции и документы/согласия по 152-ФЗ;
- политика юридических текстов: перед включением сверить оферту и
  согласие на обработку номера, журнал хранения, правила передачи номеров
  оператору, необходимые договоры и реальное расположение данных.
