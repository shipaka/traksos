# TrakSOS: курьерский маршрутный лист и нагрузка 1000
Дата: 17 ноября 2026. Статус: Draft PR #111, только изолированная ветка.

## Реализовано и границы
- Утверждение склада, оплаты и проверка поставщика остаются исключительно в админке. Курьер видит рейс только после допуска по экономике/складу.
- При создании рейса API использует только фактически проверенные GPS-координаты склада и всех получателей; если такие данные есть, сохраняет детерминированную последовательность до 50 остановок. Базовый алгоритм nearest neighbour + ограниченный 2-opt по расстоянию **по прямой**.
- Нет ни скрытого геокодирования, ни данных о дорожных знаках, развязках, пробках, платных дорогах и времени прибытия. `routeDirectKm` — геометрическая оценка, НЕ дорожный пробег.
- Если координат не хватает, сохраняется ранее согласованный ручной порядок и выводится явная отметка `manual_coordinates_missing`. Нельзя выдавать это за оптимизированный рейс.
- Каждый курьер автоматически открывает свой назначенный лист. Внутри: склад, посылки, порядок остановок, схема координат и ссылки на Яндекс Карты с промежуточными точками. Ссылки ограничены двадцатью точками и разбиваются на последовательные участки; Яндекс может менять интерфейс. Ссылка не предоставляет право на данные чужого рейса.
- Никакие GPS-запросы не выполняются в фоне без отдельного согласия курьера. Координаты и адреса вручённого или невручённого заказа скрываются из текущего маршрутного листа. Клиент видит только собственную активную остановку.
- Правила двухстороннего кода передачи, возврата на склад, приватности и блокировки двойного назначения сохранены.

## Тесты и настоящая нагрузка
`server/test/courierAutoRoute.test.ts`: реальная покупка трёх заказов/проверка адресов, смена порядка остановок, отсутствие доступа к неутверждённому и чужому рейсу, финансовое утверждение. Дополнительно — чистая детерминированность, 50 координат и честный fallback без GPS.

`.github/workflows/load-1000.yml`: один runner, отдельная временная PostgreSQL, **четыре сценария последовательно** после итогового коммита, не четыре параллельных дорогих runner'а:
1. `load-mixed-1000.mjs`: 1000 отдельных авторизованных сессий (клиенты, водители, мастера, эвакуаторы, СТО, страховые агенты, модератор и администратор), реальные 1000 одновременных GET /api/me и запросов кабинетов, 120 параллельных заявок и 40 обращений поддержки. Пользователи для теста создаются пакетно в тестовой БД: это не проверка 1000 SMS.
2. `load-community-1000.mjs`: 1000 разных аккаунтов-водителей в одной комнате, 1000 публикаций и 1000 повторов в ограниченных волнах по 100, сверка сохранённых сообщений и событий без дублей.
3. `load-community-ws-1000.mjs`: **1000 реальных** WebSocket, одноразовые билеты, 20 публикаций, до **19 980 уведомлений**, проверка отсутствия приватных полей и отзыв роли у подключённого участника.
4. `load-courier-1000.mjs`: 1000 готовых записей заказов в тестовой базе, 20 разных настоящих курьерских аккаунтов, 20 HTTP-созданий рейсов по 50 остановок и чтение маршрутов через настоящие API; сверка всех 1000 назначений, последовательностей и ACL. Для ускорения нагрузочного прогона тестовые посылки и GPS-адреса создаются SQL-фикстурой; флаг утверждения обновляется **только в тестовой базе**, поэтому этот сценарий НЕ заменяет полную финансовую приёмку из обычных интеграционных тестов.

Артефакты JSON: p50/p95/p99, время сценариев, ошибки, количество посылок, WebSocket-события, отсутствие дублей. CI на 1000 пользователей — проверка корректности и относительной производительности **одного CI runner'а**, не доказательство производительности рабочего VPS. Нагрузку на production не запускать.

## Что требуется отдельно
- Реально лицензированная маршрутизация по дорожной сети/пробкам с учётом грузовых ограничений (например, Яндекс API маршрутов): https://yandex.ru/maps-api/docs/router-api/request.html и https://yandex.ru/maps-api/docs/router-api/response.html
- Подключение лицензированного геокодера и точной зоны доставки, проверка дверей/въездов, расписаний и окон разгрузки, SLA и ETA.
- Испытание на реальном Android с 50 посылками, медленным интернетом, обновлением карты после каждой остановки, восстановлением после выхода и проверкой приватности.
- До общего успешного CI и ручной проверки не сливать Draft PR #111 в main и не деплоить VPS.
