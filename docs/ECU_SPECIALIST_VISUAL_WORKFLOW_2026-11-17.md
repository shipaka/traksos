# TrakSOS — кабинет специалиста по ЭБУ и связанные ремонтные заявки
**Дата:** 17.11.2026. **Решение:** добавлен в новую федеральную дизайн-систему как узкопрофильный исполнитель. **Статус:** подтверждённый дизайн-прототип, не production.

## Реальный технический источник
ТЗ и серверная заготовка в черновом [PR #111](https://github.com/shipaka/traksos/pull/111), документ [TRAKSOS_ECU_SPECIALIST_CASES_2026-11-17.md](https://github.com/shipaka/traksos/blob/feature/tracksos-community-ecosystem-20261116/docs/TRAKSOS_ECU_SPECIALIST_CASES_2026-11-17.md).
- Внутренняя специализация: `performer_profiles.kind='ecu'`, сервис `service='ecu'`, совместимость с существующей auth-ролью `master`.
- Логика двух типов заказов уже разрабатывается в PR #111: **прямой заказ ЭБУ** или **дополнительная заявка к ремонту** после рекомендации назначенного мастера.
- Рекомендация `POST /api/orders/:id/recommend-ecu` **не создаёт платный заказ**, клиент может согласиться/отклонить; в настоящем UI перед созданием отдельно проверяются ТС, география, тариф и условия оплаты.
- Дополнительные этапы привязаны через `orders.additional_to` / `orders.case_root_id`; свои исполнители, статусы, переписки, расчёты, претензии и гарантии. Общая сводка = список этапов, завершённые этапы и реально подтверждённые суммы; **не единый счёт**.
- Исполнитель ЭБУ может видеть только номер/вид/статус другого этапа, не чужие чаты, клиентские адреса, документы и деньги.
- Действия, связанные с прошивками, допускаются только при правовой и технической допустимости; квалификация подтверждается администрацией, не визуальной галочкой.
- При реализации не обходить существующее назначение, торги, проверку и права. Не создавать пятую публичную плитку SOS.

## Композиционная матрица
### Клиент: SOS / Заказ мастера
- На ПК и Android оставить три первых варианта SOS: **Выездной мастер, Эвакуатор, СТО**.
- После выбора «Выездной мастер» показать краткие специализации, в том числе **«Специалист по ЭБУ»** с иконкой электронного блока и реальной фотографией диагностической работы, которую можно воспроизвести в frontend. Раздел не равен «обычный диагност» и не исчезает в меню.
- На экране существующего ремонта — отдельная `CaseStagesPanel`: **Исходный мастер → рекомендация ЭБУ → решение клиента → связанный заказ ЭБУ**. Показать реальные статусы и отдельно подтверждённые суммы, не дублировать платежи.
- В карточке рекомендации: конкретная причина, авторизованный исполнитель, предупреждение «Это не новая платная заявка», отдельные действия **«Рассмотреть» / «Отклонить»**. Оформление новой работы — через самостоятельную форму, с подтверждением клиентом, без невидимого списания.
- ПК: список этапов и общее обращение в основной колонке, отдельно чат конкретной заявки и её документы/финансы. Android: последовательные полноширинные этапы, один активный CTA, удобная кнопка возврата к общему обращению. При отсутствии ЭБУ-рекомендации панель не рисует фиктивную работу.

### Специалист по ЭБУ: минималистичный профессиональный кабинет
- **На линии / На связи / Не принимать** — отдельные доступные статусы (реальный выбор только после подключения endpoint).
- Две очереди: **Самостоятельные заказы ЭБУ** и **Дополнительные этапы ремонта**.
- Карточка заявки: транспорт / признаки поломки / текущий статус / собственный чат / фото / разрешённая ТехБаза / история собственных работ. В связанных этапах **только номер, вид и статус** предыдущей работы.
- Этапы **Принять → Выехал → На месте → Завершить**; только допустимое следующее действие в каждый момент.
- Финансы показывают собственные реальные проводки; чужие чеки и выплаты запрещены. Профиль и верификация — как у выездного мастера, дополнительные специализации по разрешению.
- На ПК — рабочая очередь слева и детальный заказ справа; на Android — компактная визуальная шапка, состояние «на линии», первый активный заказ, затем очереди, ТехБаза/финансы/профиль.
- Отдельная «живая» фотография диагностического планшета/электронного оборудования в шапке + понятная пиктограмма ECU/микросхемы. Фото не выдаётся за конкретного проверенного исполнителя.

## Прототип, который уже есть (PR #121)
Источник: `design/prototypes/client-first.html`, автономный HTML/CSS/JS с локально встроенными оптимизированными иллюстрациями.
- Путь **SOS → Выездной мастер → Специалист по ЭБУ → форма → демонстрационный заказ**.
- Путь **основная заявка → имитация рекомендации мастера → решение клиента → отдельная DEMO-1043**. Статус основной DEMO-1042 при переключении DEMO-1043 не изменяется.
- **Меню → «Предпросмотр: кабинет ЭБУ (демо)»** позволяет проверить собственные очередь, статус, фото, ТехБазу и финансы. Эта опция только дизайн-лаборатории и не должна отображаться у обычного клиента на рабочем сервисе.
- Все цифры/заказы тестовые, настоящих банковских платежей/чатов/геолокации и сервера нет.
- Проверки в Chromium на **320/390/768/1440 px**, без JS pageerror и горизонтального overflow. По всему исходному прототипу прежний регресс-тест **320/360/390/768/1440 px**.
- Снимки: `ecu-desk-390.png` и `ecu-desk-1440.png` локального проверочного окружения; **настоящий Android APK не собран и не проверен**.

## Шлюзы к выпуску
1. Сверить актуальный сервер/веб из draft PR #111: `ecuDesk.tsx`, `ecuRelatedOrders.tsx`, `NewOrder`, `Order`, `ecuReferrals.ts`. Не менять эти файлы без согласования и интеграции.
2. Подключить реальную проверку `master/ecu` и серверное ACL на **каждом** маршруте, валидацию платёжного согласия и защиту от дублей.
3. Проверить 320/360/390/768/1440 Chromium, на **физическом Android** клавиатуру/назад/safe-area/медленный интернет, нотификации без двойного заказа.
4. Реальные успешные E2E: прямой заказ; рекомендация → отказ; рекомендация → создание отдельного заказа; параллельный и последовательный ремонт; возврат/претензия отдельно у каждой заявки, сводка только подтверждённого.
5. Принять визуальное совпадение фотомедиа/типографики/отступов/кнопок с реально сверстанным прототипом. До этого не менять production.

**Непреложное правило:** клиент — главный; ЭБУ легко обнаруживается внутри мастеров и в контексте реального ремонта, но не загромождает верхние SOS/Эфир экраны и не открывает доступ к чужим заказам.
