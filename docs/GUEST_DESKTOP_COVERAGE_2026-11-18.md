# TrakSOS — гостевая главная ПК, карта покрытия и тексты оферты
Дата решения: 18.11.2026. Статус: **дизайн-прототип; не production; на утверждении владельца**.

## База дизайна
- Композиция: выбранная пользователем гостевая главная, вариант №5 из сравнительной подборки.
- Вид карты: вариант №7 с географией присутствия и маркерами **только реальных, подтвержденных** партнеров.
- Услуги: SOS, Эфир (информационный вход гостя), выездной мастер, грузовой эвакуатор, СТО, консультация, стационарный ЭБУ, страхование, запчасти, ТехБаза и Клуб.
- Профессиональные фотографии тематические, оптимизированные WebP, встроенные в HTML; они **иллюстрации**, не фотографии реально зарегистрированных партнеров. Основные 6 сцен: мастер/грузовой эвакуатор/СТО/ЭБУ/консультация/запчасти.
- Шапка гостя: **«Войти» и «Регистрация» только для клиентов**; «Хочу работать с TrakSOS» — отдельный путь для выездного мастера, эвакуаторщика, СТО, страхового агента. Спецроли не оформлять через клиентскую регистрацию.
- Локация справа сверху: выбранный регион, **не автоматически полученный точный адрес / GPS**. Клиент сам меняет регион.
- RuStore — единственный согласованный магазин будущей Android-публикации. Пока не объявлять опубликованным.

## Карта — не смешивать с административным статусом
1. Географическая основа российского публичного интерфейса должна проверяться по актуальным официальным российским данным (Конституция РФ, ст. 65, ОКАТО, ОКТМО и надёжный лицензированный картопровайдер). Не нарисовывать административные границы AI-генератором. Это **не юридическое заключение** и не гарантия соответствия правилам регуляторов; отдельно согласовать с юристом и поставщиком карт.
2. Цвет отображает **фактическое операционное покрытие**, а не политический/правовой статус территории.
3. ДНР, ЛНР, Запорожская и Херсонская области — в текущем сервисном слое без подключения услуг, серым. Республика Крым и Севастополь — поддержать возможность регистрации и будущего подключения; показывать фактические точки партнеров только после проверки, не обещать услуги до запуска.
4. Все остальные регионы без подтверждённой сети также серые/«нет покрытия». Начальный технический регион SOS — СПб и ЛО; **это не значит гарантированный доступ 24/7**.
5. Не ставить ни одного фиктивного партнёрского маркера, рейтинга, ETA, активного статуса, цены и покрытия. Точки получаем из серверного разрешённого публичного feed, с проверкой статуса/адреса/разрешения публикации; точные частные адреса скрыты.
6. Отсутствие покрытия **не блокирует регистрацию**. Создание SOS-заявки/резервирование/оплата в неподдерживаемом регионе — отдельные серверные запреты по фактическому статусу услуги, а не фронтенд-цвету.
7. Регистрацию и другие сервисы ограничивать только по применимому праву, оферте и действительным возможностям; не ограничивать пользователей только из-за серого цвета.

## Карта: тексты
**Подпись:** «Карта присутствия TrakSOS».
**Легенда:** «Оранжевые точки — проверенные опубликованные партнёры; серый — нет подтверждённого сервисного покрытия».
**Для серых территорий:** «Вы можете зарегистрироваться. В выбранном регионе услуги TrakSOS пока не предоставляются».
**Для частичного покрытия:** «Доступность конкретного исполнителя уточняется при оформлении заявки; наличие точки на карте не гарантирует срочный выезд».
**Для ошибки данных:** «Карта временно недоступна. Выберите регион или повторите проверку позже».

## Оферта — черновик, требует юридического согласования
> Регистрация на платформе TrakSOS не гарантирует доступность всех услуг в регионе пользователя. Возможность оформления заказа зависит от территории обслуживания, наличия исполнителей, вида услуги и действующих условий её предоставления. Информация о доступности публикуется в интерфейсе платформы и может изменяться. Наличие региона на карте не является гарантией принятия заявки или обязательством обеспечить выезд исполнителя. Отсутствие сервисного покрытия само по себе не является основанием для отказа в регистрации, если иное не предусмотрено применимым законодательством и условиями платформы.

## Реальная интеграция
Прототип: [design/prototypes/guest-desktop-20261118.html](../design/prototypes/guest-desktop-20261118.html).

Настройки JS `window.TRAKSOS_GUEST_CONFIG`:
- `yandexMapsApiKey`: ключ для Yandex Maps JS API 3 (нужен HTTP Referer; актуальные договорные условия проверить).
- `partnersEndpoint`: **ПРОЕКТНЫЙ**, НЕ подтверждённый маршрут server API для публичных verified/active/consented точек. Feed объектов: `id,name,kind,latitude,longitude,verified,active,public_location_consent,has_approved_address`. Нельзя использовать закрытые/private координаты как публичные.
- `polygonsEndpoint`: зарезервирован под юридически и геометрически выверенные официальные административные полигоны/региональные слои; в текущем прототипе НЕ активен. **Серое закрашивание регионов пока НЕ реализовано**: есть статусные тексты и механика выбора региона. Не выдавать карту-иллюстрацию за юридически точную.
- Без настоящего ключа и backend feed прототип показывает честное пустое состояние, а не точки-фикции.
- Кнопки гостевого входа/регистрации/партнерства сейчас открывают интерактивные описания путей. Это **не подключенная авторизация**.

Локально проверено: Chromium 1440px / 390px, нет горизонтального overflow и JS pageerror, работают клиентская регистрационная модалка, выбор Крыма и ДНР, текст покрытия, раскрытие описания карты. **Не проверено**: настоящий Yandex API, юридическая точность геометрии, реальные backend endpoints, 152-ФЗ, Android APK, CI на этом commit, VPS, работа с действующими договорами партнёров.
