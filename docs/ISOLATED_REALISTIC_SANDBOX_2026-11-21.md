# TrakSOS — полноценная изолированная испытательная среда

## Назначение

**Не создавать второй набор бизнес-правил.** Тестовый клиент, водитель, автопарк,
мастер, эвакуатор, СТО, страховщик, оператор ТО, курьер, модератор и администратор
используют **те же React-кабинеты, реальные API, обработчики заказов, историю событий,
статусы, расчёт тарифов и комиссий**, что и основной TrakSOS.

Вымышленные только личности, машины, адреса и исходные ценовые данные. После
создания заявки все значения вычисляет основной код платформы. Никаких статичных
«красивых» чисел, вручную подставленных в платёжную историю.

## Изоляция обязательна

- Отдельный HTTPS origin (например, `sandbox.traksos.ru`), PostgreSQL база/volume
  `traksos_sandbox`, сетевой контур и свой `APP_SECRET`.
- `SANDBOX_INSTANCE=true`, `PAYMENT_PROVIDER=mock`, `SMS_PROVIDER=log`,
  `PUSH_PROVIDER=log`, `TRAKSOS_SANDBOX_MOCK_CHECKOUT=true`.
- Никаких действующих SMS.ru, банка, реальных контрагентов, персональных данных,
  платёжных реквизитов и доступа к production БД. Магазин остаётся закрытым.
- Проверки и тестовые операции должны запускаться только в выделенной среде;
  от CI требуется отказ при неверных флагах/DB/провайдерах.
- Служебные роли выдаются через HMAC-подписанный одноразовый ticket от
  авторизованного администратора. Не хранить известные пароли тестовых аккаунтов
  в коде, APK, документах или общих чатах.
- Фиктивные платежи, возвраты и выплаты хранятся в sandbox PostgreSQL, чтобы
  проверять поведение **после перезапуска**. Все выпуски проверяют сохранность
  проводок и идемпотентность операций.

## Контрольные сценарии

1. **Водитель → владелец автопарка → мастер.** Водитель создаёт заявку по
   закреплённому грузовику; при необходимости владелец одобряет расходы;
   мастер получает подходящую заявку, откликается; клиент подтверждает.
   Проверяем один номер заявки и согласованные статусы во всех кабинетах.
2. **Выезд мастера.** Принято → выехал → на месте → работа → завершение.
   Стоимость выезда берём из выбранного предложения, часы — из реального
   таймера, расходники — отдельными строками. Клиент и мастер видят
   согласованные суммы, документы и историю.
3. **Эвакуация.** Из заявки и самостоятельным вызовом; проверка выбранной
   машины, маршрута, исполнителя, стоимости и закрытия заказа.
4. **СТО.** Запись и работа с клиентом, карточка машины, статусы, история,
   подтверждение стоимости и переходы между мобильным и стационарным мастером.
5. **Страхование / ТО / курьер.** Настоящие внутренние заявки, назначение
   ответственного, обмен результатами и история; без выпуска реальных полисов,
   диагностических карт и отправки физических товаров.
6. **Финансовый цикл.** Условное удержание → частичное списание → завершение →
   сумма к выплате → сбор клиента → комиссия исполнителя → возврат/спор.
   Все суммы в копейках, расчёт из единого движка, общий баланс проводок
   должен равняться нулю. Повторные запросы и перезапуск не создают дублей.
7. **Доступ и безопасность.** Чужой пользователь не видит заявку,
   фотографии и суммы; модератор не получает права администратора;
   тестовая среда не видит производственную базу. Вход/выход и смена роли
   проверяются настоящими API и браузерными действиями.

## Условие публикации

На точном SHA: server tests, web build, Android/API smoke, реальные браузерные
скриншоты, межролевые заявки, financial ledger audit и sandbox image preflight.
Далее — публикация сначала в отдельную песочницу, реальные клики по кабинетам,
повторная сверка сумм и статусов, и только после этого — `main` и production
через защищённый процесс с бэкапом. Нельзя объявлять VPS обновлённым по
одному только успешному PR или скриншоту.

### Что уже реализовано, а что остаётся

Есть отдельные БД и контейнер, 12 тестовых ролей, однократные администраторские
билеты, полноценные маршруты и исходный движок заявок. В PR с этим документом
добавлены durable mock платежи, интерфейс их учебного подтверждения и CI аудит
изолированных ролей/сумм. Для **полной приёмки** всё ещё необходимы реальные
сквозные межролевые браузерные тесты именно на опубликованной песочнице и
проверенное разделение сетей на VPS; наличие исходников само по себе этого
не подтверждает.
