# TrakSOS — реализация утверждённых ПК-кабинетов (20.11.2026)

Рабочая ветка: design/owner-final-pc-cabinets-20261120, Draft PR №200. Ниже зафиксирован статус кода, а не публикация на сервере.

## Что реализовано в GitHub — первый функциональный этап

- Новый файл web/src/screens/approvedPcCabinets20261120.tsx: интерактивные ПК-пространства для девяти сценариев — водитель, владелец автопарка, мастер, эвакуаторщик, СТО, страховщик, техосмотр, модератор, администратор.
- Общая тема web/src/approvedPcCabinets20261120.css: графитовые/бирюзовые панели, оранжевые активные кнопки, широкие три рабочие колонки, читаемые карточки.
- web/src/main.tsx: маршрутизация всех девяти ПК-кабинетов. На экранах менее 1000 px возвращаются существующие мобильные/Android-компоненты, без замены утверждённого дизайна телефона.
- Реальные серверные данные и счётчики: /api/orders, /api/orders/:id, /api/fleet, /api/orders?as=performer, /api/performer/auctions, /api/base, /api/insurer/requests, /api/insurer/inspections, /api/mod/cases, /api/admin/summary, /api/admin/live. Существующие серверные ACL обязательны.
- Мастер и эвакуатор: два полноценных режима «Текущая работа» / «Новые предложения». Отклик проходит через существующий OfferForm; он не означает назначение без выбора клиента.
- Водитель и владелец: активные заявки переключаются без уменьшения рабочего пространства; сведения об исполнителе из серверного дела, GPS через RoadsideMap только со свежими координатами, чат в рабочем маршруте заказа. Неизвестные координаты/ETA не подделываются.
- СТО: входящие, в ремонте, ожидаемые приезды, готово к выдаче. Число «Ожидаем приезд» всегда равно длине реального списка, а не демонстрационным 3. Сведения о прицепе и сцепке выводятся из поступившего дела.
- Страхование и техосмотр: два отдельных полноразмерных рабочих режима одного аккаунта с двумя ролями и переключателем. Детальное страховое дело и живая форма обработки техосмотра остаются доступными в настоящих разделах. ЕАИСТО пока не подключена.
- Модерация: обзор реальной очереди и переходы в действующий разбор дела, рабочие разделы проверки и поддержки. TrakBot необязателен и на экране модератора не показан.
- Администратор: настоящая сводка, живые задачи, разделы реестра и девять тестовых кабинетов. Карта России из web/public/traksos-russia-outline.svg отображает географический контур, без вымышленных точек и статусов интеграций.
- Другие роли используют ровно согласованный ассет TrakBot /trakbot-approved-hello.webp.
- Старый Android WebView поддерживается через addListener для matchMedia.
- scripts/verify-approved.mjs расширен source-level проверками ролевых маршрутов и ассетов, не удаляя прежние защитные условия.

## Дополнительные фактические доработки текущей итерации

- Исправлен случай свежей регистрации СТО: если профиль рембазы ещё не заполнен, открывается прежнее настоящее подключение `BaseHome`, а не пустой рабочий экран.
- Android, включая широкий экран устройства, принудительно сохраняет мобильную логику по `native.isApp`; старые WebView поддерживаются.
- Для стационарного ЭБУ и ещё не зарегистрированного мастера сохранены старые действующие рабочие формы / onboarding.
- Страховой партнёр получает в центральной карточке фактически сохранённые предложения компаний и цены из `/api/insurance/requests/:id`, без придуманных сумм и без подмены оплаты.
- Модератор видит фактические обстоятельства, связанную заявку, выдержку из доступной переписки и количество записей журнала из `/api/mod/cases/:id`; решение остаётся на серверной странице с ACL.
- Содержимое SVG контурной карты России добавлено в allowlist защитной проверки ассетов, не изменяя существующие защищённые изображения.
- Source-level проверка по 12 контрольным инвариантам выполнена повторным чтением актуальных файлов из GitHub, все 12 пунктов подтвердились. **Это статическая проверка строк и маршрутов, НЕ запуск компилятора или браузера.**
- Проверка GitHub статусов последнего рабочего SHA: `statuses: []`, `workflow_runs: []`, подтверждённого прогона CI на актуальном SHA нет.

## Реализация в продолжении работы

- **Мастер и эвакуаторщик:** в карточке выбранного заказа находятся реальные серверные действия «Выехал», «Подтвердить прибытие», «Начать работу» с соблюдением порядка; завершение и расчёт остаются в штатной серверной форме, без автоматического подтверждения оплаты. Для мастера кнопка ТехБазы поверх фото транспорта. Вкладки «Работа», «Клиент и ТС», «Расчёт», «Чат», «История» в большой карточке; фотоотчёт `OrderPhotoCapture` и `OrderPhotoGallery` работают через защищённый API. Отдельные переходы ведут в авторизованные вкладки `#/order/:id/{vehicle,finance,chat,history}`, не в чужой гараж.
- **СТО:** существующий настоящий `RequestCard` используется и в новом ПК-режиме для принятия/уточнения/отказа; выбранный ремонт загружает `/api/bookings/:id` и даёт вкладки «Работа», «Клиент и ТС», «Смета», «Чат», «История». Цены и завершение не фальсифицируются.
- **Водитель/владелец:** верхние кнопки активных заявок теперь настоящие вкладки, каждая разворачивает свою полную карточку; удалён бессмысленный нерабочий переключатель. Внизу автопарка добавлены настоящая таблица заявок, фотографии зарегистрированных моделей, переходы в историю, ТО и документы. Пустые финансы и сроки ТО не заполняются демонстрационными цифрами.
- **Календарь:** точки соответствуют только записям с реальной датой. При выборе даты открываются конкретные записи и ссылки на авторизованные рабочие карточки.
- **Реальный Chromium с явно СИНТЕТИЧЕСКИМ состоянием заказа:** новый тест `e2e/approved-pc-active-work.mjs` проверяет окно мастера, шаги, внутренние вкладки, предложения и выбранную заявку владельца. Скриншоты предназначены для технической визуальной приёмки компонентов с локальными тестовыми данными, не выдаются за производственные заказы. Включён в `.github/workflows/visual-proof.yml`.
- **Живые скриншоты ролей:** обновлён `e2e/owner20-cabinet-evidence.mjs`, добавлена проверка нового десктопного DOM и снимок администратора 1672×941 с картой России. Обрабатываются честные пустые состояния кабинетов и отсутствие TrakBot у модератора.
- **Source-level защита:** `scripts/verify-approved.mjs` расширен проверками тех же инвариантов. Ручная повторная инспекция всех новых строковых контрактов и синтаксиса двух Node E2E-скриптов прошла; **это не то же самое, что успешно выполненный npm build / Playwright run**.

Обнаруженные оставшиеся функциональные разрывы: плановые записи мастера требуют реального серверного расписания с датой; этапы эвакуации «погрузка/передача» должны согласовываться с серверным workflow до добавления несуществующих переходов. Утверждённые макеты при этом не меняются.

## Что НЕ подтверждено — блокеры релиза

1. На новых коммитах пока НЕТ подтверждённых npm build, реальных Chromium скриншотов, E2E и Android smoke. GitHub Actions не запустились автоматически после коммитов через подключённое приложение. Синтаксическую и функциональную приёмку необходимо выполнить на текущем SHA.
2. Утверждённые PNG из переписки пока не помещены в репозиторий как байтовые эталоны. Структура и стиль перенесены на реальные компоненты, но соответствие «пиксель в пиксель» не доказано.
3. Детальные рабочие формы (фото, расчёты, статусные действия, полисы и переписка) пока используют прежние функциональные страницы после перехода с нового рабочего стола. Эти внутренние страницы также должны пройти визуальную приёмку.
4. Карта России пока статический географический контур. Реальные региональные точки и статистика требуют отдельной подтверждённой агрегации геоданных.
5. Нельзя выдавать mock-платежи, телефонию, SMS, выпуск полисов и диагностические карты за реально работающие внешние интеграции.
6. Проверить отсутствие регрессий у остальных ролей, мобильной версии, Android и совмещённых партнёров. Не мерджить, не развёртывать VPS без зелёных проверок и ручной приёмки.
