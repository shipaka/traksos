> Визуальный реестр утверждений владельца. Утверждение изображения НЕ означает, что код совпадает со скриншотом, что проведена E2E-приёмка или что оно опубликовано на сервере. Эталонные PNG хранятся в исходной переписке и должны быть отдельно размещены в устойчивом хранилище/репозитории перед автоматизированной пиксельной проверкой; отсутствие PNG в ветке нельзя выдавать за сохранённый референс.

## Неизменяемые общие правила

- Тёмный графитовый/сине-чёрный ПК-интерфейс, светлая читаемая типографика, выразительные оранжевые действия, реальные полезные рабочие блоки; не уменьшать весь ПК-экран до мобильного.
- Публичная главная ПК — отдельный утверждённый пользовательский исходник `617.png`, SHA256 `cde831b7a4ae09622ca68a7f699303ef0a7ae679a76d2a306eb982bc43ed5a1a`. Эталон не заменять новыми картинками.
- Обязательный единый TrakBot — оригинал «Техник №3», `web/public/trakbot-approved-hello.webp` + `trakbot-approved-30.webp`. Никогда НЕ рисовать его повторно и не заменять стандартными роботами/другими мультяшными грузовиками. Присутствие ненавязчивое; чат открывать только по нажатию.
- Фото техники выбирать только при совпадении марки и модели/поколения, историю открывать по реальному ID ТС. Не подделывать маршрут, ETA, отзывы, статусы, расчёты или «онлайн»-движение грузовиков.
- После согласования разрешены только прямо запрошенные точечные правки; не редизайн всей роли. Финальная реализация — настоящие контролы, маршруты и API, не картинка фоном. Сверка браузерных PNG на текущем SHA и ролевая/E2E-проверка обязательны до деплоя.

- **Текущая заявка открывается как отдельное рабочее окно поверх рабочего стола**, с внутренними вкладками «Работа / Клиент и ТС / Расчёт / Чат / История» и выбором других заявок СЛЕВА, карточкой ТС, проблемой, адресом, клиентом, этапами, фотоотчётом и единственным допустимым следующим действием. Не заменять это решение полноэкранным рабочим столом.
- **Без дублирования:** непосредственно НАД открытым окном заказа НЕ показывать повторные мини-вкладки «№45872 (в работе) / №45870 (заплан.) / +». Текущая заявка уже указана в заголовке окна, остальные доступны слева. Верхнюю KPI-плитку «Запланировано: 3» в финальном макете не восстанавливать; левый список отложенных записей, календарь справа и расширенный поиск остаются.
- **На верхний левый угол фотографии машины внутри заявки добавлена кнопка-книга «ТехБаза».** Она ведёт в релевантную автомобилю/неисправности ТехБазу, не ломая переход фото в карточку/историю ТС. Общие материалы доступны всем с соответствующим доступом; верифицированному специалисту с профессиональным правом доступны ОДНОВРЕМЕННО общие и закрытые дополнительные материалы. Доступ строго по серверным ACL, не по оформлению интерфейса и не только по факту наличия роли. Закрытые материалы не открываются обычным пользователям.
- **Геометрия окна:** поднимать верхнюю кромку открытой заявки в один горизонтальный ряд с верхом левого блока «Новые заявки» и правого блока «Календарь»; окно должно занимать полезную высоту до низа рабочей зоны без искусственной пустой полосы сверху. Не заменять компактные вкладки ВНУТРИ карточки. Внизу в финальном варианте видны вложения и фото, а следующая большая кнопка остаётся строго разрешённой текущим серверным этапом, без преждевременного завершения.
- **TrakBot:** в нижнем правом углу только оригинальный «Техник №3» из утверждённого файла, без нового персонажа. Утвержденный вариант сохраняет остальные цвета, элементы и позиции без перестройки.
- Последовательность действий мастера подтверждается сервером: «Принято → Выехал → На месте → Выполняется → Завершено», и финальная оплата отдельно подтверждается, не автоматически.

- **Последнее уточнение утверждённого ПК-мастера:** верхняя кнопка «Новые предложения: N» — единственная точка для непринятых заказов (по нажатию открыть входящие). В левом рабочем столбце вместо «Новые заявки» должен быть блок **«В работе (сегодня)»** с ТОЛЬКО уже принятыми мастером заявками на текущий день. Ниже — **«Запланировано»**, исключительно принятые записи на следующие дни. Непринятые предложения не дублируются слева ни в одном из этих списков. Текущая выбранная заявка из списка «В работе» открывается в большом правом окне; кнопка ТехБазы, календарь и TrakBot остаются на местах. ### Окончательная приёмка ДВУХ режимов мастера — 20.11.2026

**Пользователь прямо утвердил оба режима и переход между ними.** Эти поздние решения заменяют прежнее описание «новых предложений слева» как отдельной дублирующей колонки.

1. **«Текущая работа · N | Запланировано · M»** — первый режим рабочего стола. Открывается утверждённая полноценная заявка. Слева уже принятые мастером работы на СЕГОДНЯ, ниже отдельно подтверждённые работы на следующие дни; справа календарь/ближайшие записи. Прежний утверждённый референс: `TrakSOS_PC_master_FINAL_APPROVED_worklists_corrected.png`, SHA256 `685d94fe1a836858ad38b9ab793dd158ab2fa91adb13b26607b0a2082e08bdde`. Числа только из API, не из картинок.
2. **«Новые предложения · K»** — второй режим того же кабинета. Показывает только доступные мастеру по специальности/зоне/правам обращения клиентов, не принятые заказы. Каждая карточка: ТС, неисправность, локация, доступные подробности, кнопка **«Откликнуться»**. После отклика — **«Отклик отправлен · ожидаем выбора клиента»**; это ещё НЕ назначенная работа и не перевод в «В работе». Назначение происходит исключительно при выборе клиентом и ACK сервера. Утверждённый референс: `TrakSOS_PC_master_new_proposals_calendar_and_exact_TrakBot.png`, SHA256 `2ab5a9af027766506d719701a080136cc97f770bae89324828b8e63ac40e1ffe`.
3. **Верхняя пара переключателей** видна в обоих режимах. Активный подсвечен оранжевым, другой остаётся доступным; количества текущих, будущих и новых предложений — отдельные измерения, не суммировать их. Календарь отмечает даты с записью точками; количество/даты брать только из реальных подтверждённых данных, по клику показывать записи выбранного дня.
4. Обязателен **оригинальный TrakBot «Техник №3»**, только локальный ресурс `trakbot-approved-hello.webp`. Изображения с другими перерисованными грузовичками не являются источником утверждённого персонажа.
5. Оба PNG — эталоны из переписки, **пока не подтверждено, что они добавлены в GitHub**, реальная функциональная реализация и проверка Chrome/серверного состояния ещё впереди. Оба режима должны содержать настоящие кликабельные элементы и синхронные серверные счётчики, а не две статические картинки.
