# TrakSOS — утверждённые ПК-кабинеты · 20.11.2026

> Визуальный реестр утверждений владельца. Утверждение изображения НЕ означает, что код совпадает со скриншотом, что проведена E2E-приёмка или что оно опубликовано на сервере. Эталонные PNG хранятся в исходной переписке и должны быть отдельно размещены в устойчивом хранилище/репозитории перед автоматизированной пиксельной проверкой; отсутствие PNG в ветке нельзя выдавать за сохранённый референс.

## Неизменяемые общие правила

- Тёмный графитовый/сине-чёрный ПК-интерфейс, светлая читаемая типографика, выразительные оранжевые действия, реальные полезные рабочие блоки; не уменьшать весь ПК-экран до мобильного.
- Публичная главная ПК — отдельный утверждённый пользовательский исходник `617.png`, SHA256 `cde831b7a4ae09622ca68a7f699303ef0a7ae679a76d2a306eb982bc43ed5a1a`. Эталон не заменять новыми картинками.
- Обязательный единый TrakBot — оригинал «Техник №3», `web/public/trakbot-approved-hello.webp` + `trakbot-approved-30.webp`. Никогда НЕ рисовать его повторно и не заменять стандартными роботами/другими мультяшными грузовиками. Присутствие ненавязчивое; чат открывать только по нажатию.
- Фото техники выбирать только при совпадении марки и модели/поколения, историю открывать по реальному ID ТС. Не подделывать маршрут, ETA, отзывы, статусы, расчёты или «онлайн»-движение грузовиков.
- После согласования разрешены только прямо запрошенные точечные правки; не редизайн всей роли. Финальная реализация — настоящие контролы, маршруты и API, не картинка фоном. Сверка браузерных PNG на текущем SHA и ролевая/E2E-проверка обязательны до деплоя.

## Кабинет №1 — Водитель (ПК) — УТВЕРЖДЁН

Эталонный файл переписки: `кабинет_traksos_активные_заявки.png`, SHA256 `56daa34b379b98a21996f22c5606778835156ee50c7d32ab92178fa2a69b4fb0`.

- При наличии активной заявки вся главная поверхность посвящена ЕЙ: техника/неисправность, местоположение, исполнитель с подтверждаемым рейтингом/отзывами, карта реального пути при доступности GPS, ETA при достоверных данных, звонок/чат, последовательные статусы.
- Новую услугу можно заказать через меню, не убирая действующую заявку.
- Несколько активных заявок показываются вкладками сверху; каждая открывается в собственном ПОЛНОМ пространстве без уменьшения до нескольких мелких карточек.
- Без активной заявки — понятный рабочий стол с доступными по разрешениям владельца услугами; никаких диспетчерских функций грузоперевозок.

## Кабинет №2 — Владелец автопарка (ПК) — УТВЕРЖДЁН

Эталонный файл переписки после точечной замены TrakBot: `TrakSOS_PC_owner_APPROVED_bot_corrected.png`, SHA256 `1d94a85dbd0ac06beac79f2dbd2ca9c37ec774fa13c6cfb45a02f703b19cb61b`.

- Центр — ремонтные заявки и их отдельные вкладки, данные автомобиля, водитель, специалист, статусы, контакт, история.
- Автопарк: карточки грузовиков, кликабельная история ремонтов, документы, ТО, запчасти. Только существующие объекты владельца.
- Нет грузоперевозок, отслеживания рейсов, «в рейсе» как перевозочной диспетчеризации и карт мониторинга автопарка. Карта допустима только по конкретной заявке помощи, если присутствуют настоящие координаты.
- Итоговое изображение утверждено целиком; никаких иных визуальных правок кроме последней замены TrakBot без нового разрешения.

## Кабинет №3 — Выездной мастер (ПК) — УТВЕРЖДЁН с указанными точечными правками

Первоначальный понравившийся вариант: `TrakSOS_PC_master_concept_for_approval_v1.png`. Финальный после правок: `TrakSOS_PC_master_APPROVED_corrected.png`, SHA256 `bdbbd5f4d6940237ec8eb62e66b8fdb20bd05b4bd175432c9d4822e06cd2643b`.

- **Общая компоновка согласована:** рабочий стол со статусом «На линии», новые и срочные предложения слева, отложенные записи слева, календарь и ближайшие записи справа, поиск сверху.
- **Текущая заявка открывается как отдельное рабочее окно поверх рабочего стола**, с вкладками «Работа / Клиент и ТС / Расчёт / Чат / История», переходом между несколькими заказами, карточкой ТС, проблемой, адресом, клиентом, этапами, фотоотчётом и единственным допустимым следующим действием. Не заменять это решение полноэкранным рабочим столом.
- **Убрать дублирование:** верхнюю KPI-плитку «Запланировано: 3» удалить; количество отложенных записей остаётся в левом блоке, календарь остаётся справа. Освободившееся место отдано расширенному поиску.
- **На верхний левый угол фотографии машины внутри заявки добавлена кнопка-книга «ТехБаза».** Она ведёт в релевантную автомобилю/неисправности ТехБазу, не ломая переход фото в карточку/историю ТС. Общие материалы доступны всем с соответствующим доступом; верифицированному специалисту с профессиональным правом доступны ОДНОВРЕМЕННО общие и закрытые дополнительные материалы. Доступ строго по серверным ACL, не по оформлению интерфейса и не только по факту наличия роли. Закрытые материалы не открываются обычным пользователям.
- **TrakBot:** в нижнем правом углу только оригинальный «Техник №3» из утверждённого файла, без нового персонажа. Утвержденный вариант сохраняет остальные цвета, элементы и позиции без перестройки.
- Последовательность действий мастера подтверждается сервером: «Принято → Выехал → На месте → Выполняется → Завершено», и финальная оплата отдельно подтверждается, не автоматически.

## Барьер выпуска

Реализацию всех трёх кабинетов необходимо сделать из настоящих React-компонентов и проверить по PNG-эталонам в Chromium на реальном конечном commit SHA, включая клики, роли, карту/ETA (только при наличии фактических данных), мультизаявки, историю ТС, ACL ТехБазы, TrakBot и фото соответствующей модели. Без совпадения и согласования НЕ делать merge/deploy и не утверждать, что сервер обновлён.
