# Календарь мастера — этап 1, серверная защита резервов (#170)

Основа: ветка #169, отдельная миграция `20261119_performer_time_reservations.sql`.

**Реализовано:** хранение предложенных/выбранных/подтверждённых интервалов с UTC временем, привязкой к мастеру, клиенту, возможному заказу, событиями и уникальной защитой идемпотентности. PostgreSQL EXCLUDE USING gist блокирует одновременные подтверждения пересекающихся интервалов у одного мастера даже при двух конкурентных устройствах. Отменённая запись исключается из конфликта. Есть интеграционные тесты.

**Пока НЕ реализовано:** пользовательские действия бронирования и связь с созданием отложенной заявки, двустороннее подтверждение `proposed → selected → confirmed`, пересмотр времени по согласию, автоматическое распределение с учётом этих резервов, переключатель присутствия, Android и публичный каталог. API специально не открыто, чтобы нельзя было создать «подтверждённую запись» без настоящего заказа или разрешения сторон.

**Инварианты следующего этапа:** любые изменения только в транзакции с блокировкой исполнителя, полномочиями и idempotency; проверка конфликтов в dispatch/accept/auction, включая неопределённое время активных работ; серверная недоступность ≠ обещание отсутствия сторонних заказов. Показывать клиенту только реально подтверждённые слоты, без выдуманной занятости. Расписание в Europe/Moscow вводить в явном часовом поясе, в БД хранить timestamptz.

**НЕ MERGE и НЕ DEPLOY** до интеграции и проверок на реальных устройствах.
