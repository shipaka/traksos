# TrakSOS: проверка каждого изменения до публикации

**Обязательное правило владельца от 12 ноября 2026 года.** Любое изменение — визуальное, серверное, мобильное, в данных или маршрутах — требует повторной проверки. Отсутствие замечаний пользователя не равно одобрению новой реализации.

## На каждом push и pull request
- Проверка TypeScript/серверных тестов и сборки web.
- `node scripts/verify-approved.mjs`: зона только СПб/ЛО, исключительно грузовые услуги, RuStore, наличие и **неизменность SHA256** используемых ресурсов и сверку с единственным финальным PNG от 14 ноября, отсутствие замен на неутверждённые рисунки, наличие демонстрационной офлайн-карты.
- Playwright Chromium: открытие реальных страниц на ширинах 360, 390, 768, 1440 px; отсутствие горизонтального переполнения; по одному набору входа/регистрации; открытие SOS, входа и регистрации; ровно восемь согласованных категорий услуг; загрузка утверждённой фуры и карты.
- Playwright: сценарий без интернета (интерфейс есть, данные API не подменены кэшем), полный сквозной цикл клиента/мастера/администратора, снимки экранов, приложенные к сборке.
- Docker: успешная сборка серверного образа.
- Android: успешная release-сборка, включение в APK всех статических web-asset и проверка подписи. Новый APK нельзя называть готовым к RuStore без успешного финального теста.

## Ночью по Москве
- 01:00 — регрессионные тесты и снимки экранов.
- 01:40 — Android APK с текущими файлами сайта.
- Задачи выполняет GitHub Actions; возможна задержка очереди. Никаких самостоятельных публикаций в RuStore или на боевой сервер.

## Дополнительные ручные релизные критерии — автоматизация не гарантирует
1. Сравнить реальные скриншоты ПК/мобильного сайта/Android с **тремя согласованными изображениями**, а не с новым похожим вариантом. Автоматическая проверка хэшей не является визуальной экспертной оценкой.
2. Проверить все роли: клиент, водитель, владелец автопарка, мастер, эвакуатор, СТО, администратор, модератор. Не обещать, что они все протестированы одним браузерным сценарием.
3. Проверить телефоны разных ширин, Android при плохой сети, восстановление связи, GPS и уведомления; скорость с 3G/нестабильной сетью.
4. Проверить реальные СМС/пуши, загрузку фото и документов, историю заявок, закрытие прав доступа после выхода.
5. Соблюдение 152-ФЗ, регион БД/бэкапов, политика и договорные условия.
6. Сохранность ключа подписи APK, версия и корректность публикации в RuStore.
7. Если один обязательный тест красный, **релиз не готов**. Нельзя обходить проверку без диагностики и исправления причины.

## Принцип разработки
**Новые функции не должны менять утверждённый стиль случайно.** Мелкая графическая правка — изменение текущего утверждённого asset, а не новая композиция, и только после явного согласия владельца. При нехватке сведений лучше оставить нейтральное корректное состояние, чем выдумывать реальную модель, адрес, рейтинг, исполнителя или услугу.
