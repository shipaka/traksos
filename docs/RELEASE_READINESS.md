# TrackSOS — жёсткий предрелизный контроль (13.11.2026)

Это документ контроля запуска, не утверждение, что реальный сервер уже работает. Релиз не считается готовым по одной зелёной сборке.

## Подтверждено кодом / автоматическими проверками

- Четыре рабочих кабинета (клиент, исполнитель, СТО, администратор) и отдельный страховой тип. Верхняя кнопка «☰ Меню», внизу — основные действия и магазин. При роли `master_service` два рабочих кабинета и переходы в обе стороны. `e2e/flow.mjs` проверяет их.
- Выездные специальности мастера отдельно от услуг СТО, по выбранным специализациям работает распределение заявок. Тест `server/test/domain.test.ts`.
- SMS — регистрация / восстановление, обычный вход по паролю. Проверка несовместимых ролей на сервере. `server/test/auth_password_roles.test.ts`.
- Лимиты SMS (номер / IP) и пароля (номер / IP) транзакционные, переживают перезапуск и общие для экземпляров сервера. Проксирование IP доверено только внутреннему reverse proxy при `TRUST_PROXY=true`. Таблицы `auth_sms_limits`, `auth_login_attempts`, почасовая очистка.
- Push-токен закрепляется за действующей сессией, повторная регистрация того же устройства у другого человека снимает старую привязку. Сброс пароля отзывает старые сессии и push-токены. Тест `server/test/push_sessions.test.ts`.
- Магазин доступен в навигации, но **выключен по умолчанию** на сервере. Реальная оплата не включается без отдельных юридических/платёжных проверок. Покупки из страхового кабинета запрещены.
- Docker Compose + Caddy HTTPS, PostgreSQL и резервная копия `deploy/backup.sh` через атомарный custom dump и `pg_restore --list`; проверка shell/Compose — в CI.

## Блокирует публичное использование реальными людьми

1. **Российский VPS, DNS и HTTPS**: предоставить оплаченный VPS, настроить A-запись `traksos.ru`, подключить `траксос.рф` после основного домена. Процесс `deploy/LAUNCH.md`. Сервер ещё не подтверждён работающим.
2. **Настоящие SMS**: `SMS_PROVIDER=smsru`, настроить SMSRU_API_ID только на VPS, проверить регистрацию и восстановление пароля на собственном телефоне. `SMS_PROVIDER=log` — только закрытый техностенд, не рабочая регистрация.
3. **RuStore Push**: действующие RUSTORE_PROJECT_ID и RUSTORE_SERVICE_TOKEN, `PUSH_PROVIDER=rustore`, корректный проект, разрешения Android и тест на реальном устройстве с заблокированным экраном / в фоне / после перезагрузки. Доставка push зависит от ОС и связи; не гарантировать вызов после принудительной остановки.
4. **Android APK**: проверить на физическом Android вход по паролю, opt-in отпечаток / системный PIN, отказ от разблокировки, вызов на фоне, «На линии», приём/отказ и возврат в приложение. Для RuStore нужен релизный ключ подписи, debug APK не публиковать. Сборка сама по себе не доказывает пункты.
5. **152-ФЗ и документы**: юрист/оператор ПД проверяет договоры, оферты, политику, хранение документов, уведомление РКН (при применимости), условия российского размещения и передачи в сервисы; нельзя объявлять это решённым автоматическим тестом.
6. **Деньги и магазин**: до проверки юридической агентской схемы, чеков, ЮKassa и выплат `PAYMENT_PROVIDER=mock`, магазин `enabled=false`, реальных платежей нет.
7. **Бэкапы и мониторинг**: подтвердить ежедневный dump, выполнить пробный restore в `traksos_restore_test`, настроить внешние резервные копии, ограничить SSH и проверить HTTPS/доступность. Dump на том же VPS не спасает при потере сервера.

## Перед любым релизом

- Сверить последний `main` commit с последним **зелёным** run «Проверка» в `https://github.com/shipaka/traksos/actions`. Если run красный/отменён/выполняется, это не готовый релиз.
- Из run скачать артефакт `screens`, визуально проверить домашние страницы клиента, мастера, СТО и администратора на мобильном/десктопе, включая `21-hybrid-master` и `22-hybrid-service`. Проверять и кнопки, не только скриншоты.
- Android workflow «Android» на `main` запускается по изменениям веба/Android и каждую ночь; убедиться в зелёной сборке APK актуального кода и в верной `APP_URL`.
- «Образ сервера» публикует образ GHCR только после успешного полного CI соответствующего коммита. Не путать свежий `main` с образом `latest` от предыдущего зелёного коммита.
- Не менять согласованные грузовик/карту/фотографии и дизайн без явного запроса. Использовать `scripts/verify-approved.mjs`.
