# TrackSOS — независимый бухгалтерский журнал агентских закупок

**Область:** issue #123, проект правовой модели #122, требования PR #124.  
**Ветка:** feature/shop-agent-evidence-ledger-20261117.  
**Статус:** изолированное серверное ядро, магазин и реальные платежи не изменены.

## Реализовано в новом, не пересекающемся с PR #111 модуле

- Миграция 160 создаёт три отдельных хранилища: строки закупки, события,
  неизменяемые снимки экспортов. UPDATE/DELETE запрещены PostgreSQL-триггерами.
- Суммы в целых копейках, поставщик, заказ, покупатель/ИНН, договорная модель,
  подтверждённое поручение, снимок оферты, версии вознаграждений и две
  отдельные комиссии хранятся по каждой строке.
- Повтор импорта строки или события с тем же идентификатором не дублирует
  суммы. Повтор ключа с другим содержимым отклоняется. Исправления,
  возвраты и дополнительные платежи фиксируются новыми событиями.
- Отдельно различаются котировка поставщика, первичный документ, оплата
  поставщику, поступление средств покупателя, возврат, передача,
  отчёт агента и подтверждение. Проверяются сумма и количество
  распределения одного УПД на несколько товарных строк.
- Проверяются поручение ДО фактической закупки, доказательство договора
  при агентировании поставщика, отсутствие смешения собственной
  перепродажи с агентскими услугами, НДС по первичным документам,
  недопоставка, перепоставка и расхождения финансовых компонентов.
- Для клиента-агента предварительный денежный доход — только
  отдельно разнесённые агентские и сервисные поступления минус возвраты.
  Для собственной перепродажи — поступления за собственную реализацию.
  Никакая разница «цена клиента минус API-котировка» не принимается за доход.
- Отчёты день, неделя (Пн–Вс), месяц и диапазон с границами МСК UTC+3,
  агрегаты по компаниям, отдельная сумма бухгалтерски одобренных строк,
  CSV с защитой от формул Excel и SHA-256 снимка.
- Доступ к модулю — только администратору; действия записываются в
  существующий audit_log. Каждое подтверждение привязано к хешу фактов.
  После любого нового факта предыдущее подтверждение устаревает.

## Границы безопасности

**Это не действующий налоговый кабинет и не автоматическое закрытие налогов.**
Не изменены server/src/app.ts, web/src/main.tsx, магазин, Android,
платёжный сервис, действующие расчёты или конфигурация VPS.
API-маршруты и UI пока намеренно не подключены, чтобы не конфликтовать
с параллельными PR #111, #121, #137. Нет автоматического импорта
из Автоконтинента и связи с настоящими выписками ЮKassa/банка.
Предполагаемое подтверждение бухгалтером означает ручной акт админа,
не ЭЦП/ЭДО. Оригиналы УПД нужно хранить в отдельном защищённом
хранилище, а SHA-256 исходников проверять при дальнейшем подключении.

Экспорт CSV — внутренний аналитический документ. Ни отчёт, ни пример
УСН 6%, ни пометка accountant_approved **не заменяют декларацию,
КУДиР или правовое заключение**. НДС и налоговая база требуют
подтверждения действующей модели агентирования юристом/бухгалтером
по issue #122. Магазин по-прежнему закрыт до отдельного решения.

## Изолированный инструмент для проверки

Файл server/src/ops/shopAgentLedgerCli.ts доступен только при всех
трёх условиях: SANDBOX_INSTANCE=true,
SHOP_AGENT_LEDGER_SANDBOX_CLI=yes и явном DATABASE_URL с подстрокой
«sandbox», плюс SHOP_AGENT_ADMIN_ID — UUID активного
администратора именно тестовой базы. Существующие дополнительные
правила sandbox из server/src/config.ts сохраняются.

Из директории server после миграции тестовой БД:

    npx tsx src/ops/shopAgentLedgerCli.ts create-line /tmp/line.json
    npx tsx src/ops/shopAgentLedgerCli.ts event ORD-1-ITEM-1 /tmp/event.json
    npx tsx src/ops/shopAgentLedgerCli.ts inspect ORD-1-ITEM-1
    npx tsx src/ops/shopAgentLedgerCli.ts report day 2026-11-17
    npx tsx src/ops/shopAgentLedgerCli.ts report week 2026-11-17 7800000000
    npx tsx src/ops/shopAgentLedgerCli.ts csv month 2026-11-17 > /secure/agent-report.csv
