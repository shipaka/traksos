# SOS: явное подтверждение региона и тарифной зоны (релизный блокер #113)

## Что защищает этот этап

При создании нового выездного SOS клиент отдельно выбирает **регион местонахождения машины** (Санкт-Петербург / Ленинградская область / другой регион), затем одну из опубликованных **тарифных зон только для этого региона**. До обоих выборов сумма не показывается. IP и координаты **не выбирают регион либо тарифную зону автоматически**.

На сервере одно и то же строгое правило выполняется:
- через `POST /api/pricing/estimate` — **до показа суммы**;
- через `POST /api/orders` — **до INSERT, удержания денег и диспетчеризации**;
- через `OrdersService.launch` для заявки с подтверждением владельцем — **снова до создания платежа**.

Указанная `regionId` сохраняется в `orders.location_region`, тариф в `orders.zone_id`. Все существующие до миграции заказы имеют `location_region=NULL`: **их согласованные суммы, банковские операции, гарантии и отмены не пересчитываются**. Повторное открытие старого заказа также не обновляет его регион вслед за текущими настройками формы.

Для неподдерживаемых регионов система не создаёт заказ или платежи по тарифам КАД: показывает предложение обратиться за отдельным согласованием стоимости и доступности. **Это не выдаётся за уже готовую систему автоматического федерального диспетчерского сервиса**. Консультации по телефону допускаются без тарифа поездки.

## Почему здесь нет ложной «точности GPS»

У платформы ещё нет согласованного надёжного геокодера/полигонов КАД с лицензией. Простые географические прямоугольники и расстояния до известных населённых пунктов — только **фильтр заведомо неверных сочетаний**: Москва/Калининград/Владивосток, координата далеко от названного города и т.п. Они **не доказывают**, что машина действительно внутри КАД или что дорога до неё равна 30 км.

Отображаемая стоимость явно помечена **предварительной**. Финальные цена подачи, дорожный маршрут/ETA, дополнительная работа и согласие клиента должны определяться отдельно. Пользователь может указать адрес без GPS (но с распознаваемым городом), либо вручную нажать «Использовать мою GPS-точку»; если он оформляет заказ за водителя в другом городе, текущая GPS-точка пользователя не подставляется автоматически. При смене региона/зоны/адреса показ старой сметы сбрасывается до получения нового ответа сервера.

Миграция: `117_sos_location_region.sql`. Поля `regionId` и `zoneId` обязательны для новой выездной заявки; для существующих интеграций без региона сервер возвращает явную ошибку `region_required`, а не молча принимает «СПб». Это **осознанное несовместимое изменение API**. Тестовые старые фикстуры получают явную пилотную область только в `server/test/helpers.ts`; в реальном серверном маршруте такого fallback нет.

## Приёмка и ограничения

Проверить в disposable PostgreSQL + mock provider:
- СПб / Ленобласть с адресом без GPS; отдельные подходящие зоны;
- Москва, Калининград, Владивосток, противоречивое city/region/zoneId, GPS вне контура, частичные координаты;
- точка на грубой границе покрытия и сразу за ней; GPS без текстового адреса;
- прямое `POST /api/orders` без regionId: **400**, ноль заказов и банковских намерений;
- новый заказ в СПб, затем выбор Ленобласти в форме: уже созданный заказ/сумма не меняются;
- мобильная ширина 390px и ПК 1440px: никаких автоматических цен, ручное согласование вне покрытия, отсутствие «застрявшей» старой цены.

**Остаточные задачи перед федеральным запуском**: юридически лицензированные геоданные, фактический полигон зоны КАД, дорожные маршруты и ETA, административно утверждённые региональные тарифы или полноценный workflow индивидуальных смет, каталог реальных доступных исполнителей по регионам, местные часовые пояса за пределами СПб/ЛО. На данном этапе оба поддерживаемых региона используют Europe/Moscow; федеральную временную зону не подменяем Москвой, поскольку выезд вне этих регионов пока запрещён. Магазин запчастей остаётся отдельным **СПб-ограниченным** сервисом; его поведение не затрагивается.

Ни реальные платежи, ни production VPS этот PR не включает. Объединение только после CI/Android/E2E. Полностью закрыть федеральный релизный блокер #113 можно лишь после подтверждения внешнего геосервиса и региональных тарифных зон.
