# Точка Банк — счета B2B в TrakSOS (19.11.2026)

## Решение владельца
- Точка — основной банк для счетов юридическим лицам и ИП; ЮKassa не включать по умолчанию.
- Наличные за платформенные заявки не предлагать в целевой модели. Запрет наличных для новых заявок введён; старые проводки и расчёты сохраняются для корректного исторического учёта. Новые банковские операции требуют отдельного подключения и тестов.
- Договорная модель: 5% сервисного сбора с клиента сверх цены работ + 5% комиссии исполнителя из цены работ; предел 5 000 рублей **для каждой стороны**. Клиенту не раскрывать внутреннюю комиссию исполнителя.
- Банк и интернет-кассу, НДС принципала, роль TrakSOS при выставлении счета требуется согласовать с юристом/бухгалтером и Точкой до первого реального платежа.

## Что реализовано в этом PR
- Отдельный адаптер документации Точка.API: создание счета, PDF, отправка email, GET статуса оплаты.
- Защищённые admin-only эндпоинты, проверка ИНН и сумм. Никто из клиентов и исполнителей не может выписывать банковские документы без админа.
- PostgreSQL-журнал: один внутренний платеж = максимум один исходящий запрос на создание банковского счета. При неопределенном ответе — блокировка повторного создания и ручная проверка в Точке.
- Чёткое разделение суммы работ и клиентского сервисного сбора на позиции счета. Ставки НДС для каждой позиции администратор **должен указать явно**, без опасного значения по умолчанию.
- Банковский статус счета показывает только индикатор. **Не изменяет статус внутреннего платежа, не создаёт ledger-проводки, не открывает выезд, не запускает выплату, не считается доказательством получения денег.**
- По умолчанию сервис выключен; тестовая/демо-песочница никогда не обращается к реальному банку.

## Переменные окружения — только VPS, не GitHub
```dotenv
TOCHKA_INVOICE_ENABLED=false
TOCHKA_API_TOKEN=
TOCHKA_CUSTOMER_CODE=
TOCHKA_ACCOUNT_ID=
```
Токен JWT создаётся в личном кабинете Точки с разрешением **ManageInvoiceData**.
`TOCHKA_CUSTOMER_CODE` — девятизначный код вашей компании (Get Customers List).
`TOCHKA_ACCOUNT_ID` — номер расчётного счёта / БИК, например `40702810000000000000/044525104`. Это пример формата, не реальные реквизиты. Документация: https://developers.tochka.com/docs/tochka-api/opisanie-metodov/vystavlenie-schetov-i-sozdanie-zakryvayushih-dokumentov/schet-na-oplatu

Не включать `TOCHKA_INVOICE_ENABLED=true` до согласования формы агентского счета и разрешения на реальные банковские запросы. Песочница Точки и отдельная продуктовая песочница TrakSOS — разные среды.

## API для административного кабинета
После того как в таблице `payments` существует `pending`-платёж с `method='invoice'`, `kind='work'`:

```http
POST /api/admin/payments/{paymentId}/tochka-invoice
Authorization: Bearer <admin session token>
Content-Type: application/json

{
  "buyer": {
    "type": "company",
    "taxCode": "7701234567",
    "secondSideName": "ООО Автопарк",
    "kpp": "770101001"
  },
  "workVat": "without_nds",
  "serviceVat": "without_nds"
}
```
**Пример кода не утверждает фактическую ставку НДС — её нужно проверить отдельно для исполнителя и платформы.**

Дополнительные маршруты:
- `GET /api/admin/payments/{paymentId}/tochka-invoice` — локальный документ и состояние.
- `GET /api/admin/payments/{paymentId}/tochka-invoice/pdf` — PDF от банка.
- `POST /api/admin/payments/{paymentId}/tochka-invoice/email` с телом `{"email":"buh@example.com"}` — отправить счёт бухгалтерии.
- `GET /api/admin/payments/{paymentId}/tochka-invoice/bank-status` — проверить отображаемый банком статус без бухгалтерской проводки.

Следующий UI-этап: кнопки «Выставить счёт», «Скачать PDF», «Отправить бухгалтерии», «Проверить», доступные только администратору. Отдельно сделать кабинет компании для просмотра собственных счетов (по правам доступа), не раскрывая банковские данные других организаций.

## Почему банк не подтверждает платеж автоматически
Точка связывает статус счёта с платежами по ИНН, точной сумме и номеру в назначении; **отметку также можно изменить вручную в интернет-банке**. Статус документа `payment_paid` поэтому нельзя безусловно использовать как доказательство поступления средств. Следующий этап — подписанные уведомления и чтение выписки, сверка уникального bank payment ID, счёта зачисления, ИНН отправителя, суммы и номера заказа. Отдельно обработать частичную оплату и возвраты. До этого реальный заказ нельзя переводить в «оплачено» по одному флагу счета.

## Что ещё НЕ подключено
1. Приём от физлиц через СБП, B2B QR, карточный эквайринг Точки и двухэтапное резервирование.
2. Реальные выплаты исполнителям, номинальный счёт Cyclops, автоматическая сверка входящих платежей, онлайн-касса/чеки 54-ФЗ.
3. Автоматическая выдача счета из кабинета клиента; здесь пока безопасная админская точка входа.
4. Приём/пересылка **входящих** PDF-счетов от сторонних компаний — отдельный документооборот.
5. Включение реального банковского токена и любые изменения VPS.

Для номинальных счетов Cyclops понадобится отдельное согласование с Точкой, в том числе IP-адреса сервера, плюс сертификаты/подписи: https://developers.tochka.com/docs/cyclops/interaction/

## Проверки
`npm run typecheck --workspace @traksos/server` и `npm test --workspace @traksos/server` — в CI. Тесты `server/test/tochkaInvoices.test.ts` проверяют сумму и разделение комиссий, запрет повторной выдачи при неясном ответе и то, что банковский статус не делает заказ оплаченным.
