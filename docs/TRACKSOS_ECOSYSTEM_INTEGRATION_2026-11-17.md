# TrackSOS — интеграционная карта всей экосистемы, 17.11.2026

**Владелец решения:** продукт TrackSOS. **Основная ветка:** Draft PR #111, issue #110. **Отдельный дизайн:** Draft PR #121. **Обязательное правило:** ни один пункт ниже не считается выпущенным пользователям, пока не пройдены CI, приемка, мобильный WebView и staging. Main/Timeweb не менять из этого документа.

## Общий принцип

TrackSOS — единая клиентская платформа по обслуживанию грузового и коммерческого транспорта с профессиональными сообществами, Эфиром водителей, ТехБазой, магазином, логистикой и страхованием. Приоритет интерфейса: **клиент/владелец/водитель → SOS и Эфир → активные заявки → остальные сервисы**. Не показывать национальный охват исполнителей там, где нет реально проверенных партнёров. До реального подтверждения нет ETA, цены, наличия, доставки или «онлайн».

Степени готовности не смешивать: **ТЗ → код в Draft → CI → ручной staging → APK/устройство → приемка дизайна/юридических процессов → разрешенный production**.

## Этап I. Связанные заказы и узкие специалисты (интеграция)

- **ЭБУ**: профессиональное название «Специалист по ЭБУ и автомобильной электронике»; профиль `performer_profiles.kind='ecu'`, существующая мастерская роль `master` без нового неподконтрольного системного ACL. Проверка документов исполнителя обязательна.
- Код Draft: `server/migrations/146_ecu_specialist_linked_orders.sql`, `server/src/services/ecuReferrals.ts`, `server/src/services/orders.ts`, `web/src/screens/ecuDesk.tsx`. Добавлены маршрутизация кабинета `web/src/main.tsx` и контроль клиента/связанных этапов `web/src/screens/ecuReferralPanel.tsx`; форма заказа `web/src/screens/client.tsx` использует `additionalTo`.
- Рабочий пример: электрик → рекомендует ЭБУ с причиной → владелец принимает или отклоняет → отдельный новый заказ ЭБУ с собственными торгами, ценой, статусами и исполнителем → все этапы видны клиенту в одной ремонтной истории. Рекомендация **сама не создает обязательства**.
- Исполнителю доступно только существование смежного этапа и его статус. Цены, чаты, контактные данные, платежи и приватные заметки других подрядчиков не раскрывать.
- Отсутствие общей заявки-«мешка»: `case_root_id` объединяет историю, не смешивает договоры, комиссии, выплаты, гарантию и споры.
- Тесты: `server/test/ecuReferrals.test.ts` — ACL, клиентское решение, одна активная дополнительная заявка, отсутствие чужих платежей. **Только наличие теста не подтверждает его прохождения.**
- Дальше: последовательно разрешать другие типы добавочных работ через конфигурируемые совместимые специализации, без произвольного `additionalTo` и без обхода тарифной географии; пока сервер сознательно допускает только ECU.

## Этап II. Эфир + TrackSOS Клуб

- Существующие серверные контуры `community`, `communityDirect`, `communityRoad`, `communityNotifications`, real-time ticket/reconnect; в интерфейсе `driverAir.tsx`.
- Утверждены: публичный/городской/маршрутный Эфир, псевдонимы, подписки, согласованные личные чаты, антиспам, жалобы, приватность и добровольное местоположение.
- Отдельно обрабатывать контент, ACL, злоупотребления, закрытие нежелательных диалогов; события с TTL и удаление старых данных.
- **Проверки:** 200 реальных WebSocket соединений, 200 пишущих в комнату, слабая сеть, reconnect/backoff, курсоры и пагинация, клиент Android, запрет публичных GPS и регистрационных телефонов.
- Приоритет следующей UI-интеграции: Эфир на первом клиентском экране рядом с SOS, без отдельного приложения; утверждение компоновки через #121, а не подмена рабочего кабинета мокапом.
- **Выявлен блокер #125:** владелец `client` может сам водить машину, но пока водительский Эфир жёстко требует роль `driver`, а несовместимость ролей запрещает их сочетание. Подготовить явное включение Эфира владельцем без второй учётной записи, с отдельным ником и сквозными ACL/DM/пуш/WS-тестами. До завершения #125 не заявлять, что Эфир доступен всем владельцам.

## Этап III. Профессиональные клубы и ТехБаза

- Сложные случаи из диагностики, ТехБаза конкретного ТС, марки и электронных систем, связь с заказом без раскрытия ФИО/телефона/адреса.
- Источник, применимость VIN/модификации, права на изображения и схемы, дата редакции и квалифицированная модерация — обязательные условия **до** публикации как проверенного материала.
- Ветка включает справочники и формы технических случаев, жалобы/апелляции, ссылки производителей; это не полная лицензированная библиотека всех моделей.
- Следующий приемочный пакет: EBS/ABS, ECM/EDC, коробка/ретардер, иммобилайзер; матрица доступа, лицензии, точность вариантов, «не знаю» вместо выдуманной схемы, offline кеш только разрешённых материалов.
- **Интеграционный пакет 17.11:** приватная связь `community_technical_case_order_links` из миграции `148_technical_case_private_order_links.sql`. Авторизованный подтверждённый исполнитель при явной отправке обезличенного вопроса может позже открыть его из своей заявки через `GET /api/community/pro-cases/for-order/:id`; коллеги видят только техполя, **не видят идентификатор или связь с заказом**. Контроль текущего назначения, специализации, модерации, повторного clientNonce, архивного просмотра после завершения. Смена исполнителя лишает доступа к прежнему личному мосту. UI в `web/src/screens/professionalCases.tsx`. Тест `server/test/communityOrderPrivateLinks.test.ts`. Экспорт личных данных автора включает ссылки; при удалении их удаляют CASCADE через удаление авторских кейсов/заказов.
- Ни одна рекомендация из клуба не создаёт SOS, платежи, назначение ЭБУ или другую услугу: только отдельное добровольное решение клиента через нормальную заявку и тарифный расчёт. Клубный ответ и неподтверждённый материал не становятся проверенной инструкцией ТехБазы автоматически.

## Этап IV. Магазин запчастей + склад + доставка (только Санкт-Петербург на старте)

- Отдельный `ShopRegionService` закрывает витрину, цену и оформление вне подтверждённого региона; не определять право покупки по IP.
- История заказов, закупочные снимки, подтверждение артикула/партии, расхождения склада, статусы поставщика, доходность заказа/маршрута, курьер с маршрутом и согласованным GPS.
- Никаких обещаний наличия по данным без подтверждённого API/первички Автоконтинента; выдача клиенту только после двухстороннего подтверждения, без автоматического «деньги возвращены» при возврате посылки.
- **Особый блокер:** первичка и аудит агентского налогового учёта по каждому заказу, независимая закупка/возмещение/вознаграждение, фиксирование редакции оферты; юридическое подтверждение комиссии/наценки и эквайринга. Текущая формула не является правовой и кассовой приемкой.
- **До выпуска:** реальное поступление от поставщика, геокодирование адресов, ручная физическая складская сверка, безопасность GPS, тесты хода курьера на Android, выдача без смартфона, интеграция платежей.

## Этап V. Исполнители, уровни, финансы, доверие

- Включить отдельные личные кабинеты всех профессий и административную песочницу; не ломать существующие права, меню и клиентские заявки.
- `Старт → Активный → Приоритетный` — объяснимый ручной пересмотр с учётом реального предложения заказов; нет автоматического понижения за низкий спрос, нет «наказания за работу вне платформы».
- Отдельно проверить налоговую схему комиссии платформы, оплату мастеру, историю гарантий/споров, денежную ответственность, возвраты **после** подтверждения банком/администратором в соответствующем процессе.
- Экономика доставок и деньги выездных исполнителей — разные подсистемы, их нельзя смешивать.

## Этап VI. Национальная география + адаптивный премиальный интерфейс

- Национальное позиционирование бренда **не равно** национальной проверенной диспетчеризации. Платный SOS по новым территориям блокировать до доступных исполнителей, карты сервиса, геокодирования и региональной схемы цены (см. issue #113).
- Отдельный визуальный PR #121 содержит демонстрационный клиентский HTML с двумя главными действиями SOS/Эфир, его **нельзя считать production API или реальным APK**.
- Переносить в общий React-frontend поэтапно после утверждения: client-first, кабинеты ролей, связанные заявки, уведомления, слабая сеть, анимация с reduced-motion, скорость экрана 320–1440 px и Android WebView. Не пересобирать весь CSS без потребности.
- APK/PIN/биометрия (#108), безопасность регистраций/SMS, навигация «Назад», финансовые блокеры и авторизация — самостоятельные P0-gates.

4. Протестировать web PC / mobile web / Android WebView: 320/360/390/768/1440, поворот, перезапуск, слабая сеть, кнопки Назад и восстановление после потери соединения.
5. Сверить API, дизайн и режимы безопасности с параллельными PR. **Нельзя объединять #111/#121/#108 механически**; только после review конфликтов и явного решения о релизе.
6. Пакет запуска: миграционный план с rollback, подтверждённый staging, матрица доступов, юридические/финансовые стоп-факторы, подтверждение владельца. До этого PR остаётся Draft и закрытые функции — закрыты.
