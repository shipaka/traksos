# TrakBot «Техник» v3 — безопасная 3D-визуализация

Дата: 21.11.2026. **Проектное решение для интерфейса, не разрешение менять утверждённую внешность или выкладывать на VPS.**

## Что имеется и что невозможно сделать одним CSS

`TrakBotMascot` уже имеет **30 утверждённых реакций** (атлас WebP) и отдельную приветственную позу; `TrakBotDock` отдельно отвечает за пользовательское открытие/закрытие, адаптивные размеры, скролл и фокус. Их API не зависят от визуального движка. Текущий утверждённый ассет — плоская наклейка в прямоугольном кадре с белым фоном. `border-radius`, `mask-image`, `filter`, `mix-blend-mode` могут скрыть углы и придать глубину, но **не создают геометрию 3D и не восстанавливают скрытые пиксели**. Белый фон при multiply может затемнить белую кабину: это временный компромисс, не итоговый ассет.

## Рекомендуемая реализация без вмешательства в бизнес-логику

**Этап 1 — основной путь (объёмный 2.5D):** получить из ТОГО ЖЕ персонажа v3 индивидуальный прозрачный WebP/PNG 512–1024px: белая кабина, оранжевые акценты, тёмная кепка, улыбка, планшет, без белого квадрата, чужих деталей и обводки. Создавать рендер нужно по утверждённому оригиналу и перед заменой показать владельцу. Использовать локальный файл (не CDN) и его 2–4 оригинальных состояния, CSS-анимацию покачивания 3–5 секунд, лёгкое появление и тень. `position:fixed` для сайта ПК, соблюдать нижнюю навигацию на телефоне, в Android оставить вход в TrakBot из меню, пока отдельно не согласовано плавающее окно. Hover/pointer — только лёгкая анимация; никаких автоматических чатов.

**Этап 2 — только по желанию владельца (настоящий WebGL 3D):** использовать отдельную модель GLB/glTF и лёгкий standalone canvas. Устанавливать по запросу или при видимости, с паузой вне окна и резервным прозрачным WebP при ошибке, недоступном WebGL или reduced-motion. Не добавлять Three.js/другие движки в стартовый общий bundle, не создавать постоянный render loop по умолчанию. 3D не должно менять React-маршрутизацию, телефонный ввод, авторизацию, API, статистику и заявки.

## Контракт замены медиа

- `APPROVED_VISUALS` хранит ссылку на **одну** актуальную фирменную модель/прозрачное изображение и старую sprite-серию для реакций.
- `TrakBotMascot` получает только изображение, состояние и размер. `TrakBotDock` остаётся единственной точкой клика, доступной клавиатуре.
- Не ломать 30 реакций, aria-label, Escape, закрытие при смене маршрута, восстановление фокуса, приватность данных.
- Протестировать в реальном браузере 320, 390, 768, 900, 960, 1200, 1440, 1536; отдельно в WebView/APK. Контролировать перекрытие CTA, bottom tabbar, прокрутку, выход из чата, производительность, reduced-motion и доступность картинки офлайн.
- Новое изображение становится каноническим **только после согласования владельцем**. До этого не заменять лицо и силуэт, не маскировать нарушение дизайна новым 3D-роботом.

### Решение по техническому риску

Первый этап **низкорисковый**, потому что это изменение слоя ассетов и CSS; второй средне/высокорисковый для Android/WebView и не требуется для появления объёмного живого персонажа в текущем релизе. Сначала закончить единый интерфейс и реальные E2E.
