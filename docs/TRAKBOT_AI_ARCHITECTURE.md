# TrakBot: ИИ через API или на своём сервере

Дата разработки: 19.11.2026. Документ для команды разработки. **Ничего не включать на production без согласования и проверки.**

## Что где работает

- **Всегда на сервере TrakSOS:** личные сообщения, PostgreSQL со справочником и кейсами ремонтов, поиск кодов, доступ по ролям, навигация, согласие, защита от опасных советов, лимиты, согласованная финансовая логика.
- **Внешний API (опционально):** LLM для осмысленной нейтральной беседы и составления объяснений *только на основе уже найденных надёжных данных*. Ключ хранится исключительно на сервере. Внешний ИИ никогда не управляет заказами, чатами мастеров и списаниями.
- **Локальный inference (опционально):** модель, которую владелец устанавливает отдельно и обслуживает на том же сервере (или за локальным прокси). Для совместимости требуется OpenAI-style `/v1/chat/completions`, например vLLM. Не следует путать такое программное совместимое API с обязательной услугой OpenAI: локальный inference не требует внешней подписки.
- **Без модели:** работоспособный бесплатный справочник, простые ответы и подсказки по интерфейсу, приватная история. Никаких обращений к внешнему ИИ.

## Режимы (выбирается ровно один)

В текущем PR внешний интеллект **выключен**, чтобы он не отправлял пользовательские обращения никуда автоматически.

### Режим 0: только сервер TrakSOS (сейчас)

```dotenv
TRAKBOT_LLM_ENABLED=false
TRAKBOT_LLM_TRANSPORT=off
```

### Режим 1: внешний API

```dotenv
TRAKBOT_LLM_ENABLED=true
TRAKBOT_LLM_TRANSPORT=api
TRAKBOT_LLM_API_KEY=...  # исключительно секретное окружение VPS, никогда в GitHub
TRAKBOT_LLM_MODEL=...    # действительно доступная модели и права аккаунта
```

Используется фиксированный HTTPS-адрес OpenAI Responses API. Для внешнего API нужен отдельный платёжный аккаунт и API-ключ: подписка на потребительский ChatGPT сама по себе не предоставляет бесплатные API-запросы. Тарификация обычно зависит от обработанных/сгенерированных токенов и выбранной модели; бюджет и лимиты надо задать до включения пилота.

### Режим 2: собственная модель на том же сервере

```dotenv
TRAKBOT_LLM_ENABLED=true
TRAKBOT_LLM_TRANSPORT=local
TRAKBOT_LLM_LOCAL_URL=http://127.0.0.1:8000/v1/chat/completions
TRAKBOT_LLM_MODEL=...    # имя реально обслуживаемой локальной модели
```

Протокол локального сервера — OpenAI-compatible Chat Completions. Внешний API-ключ не нужен; HTTP-адрес настраивается **строго для loopback** и пути `/v1/chat/completions`, чтобы изменение окружения не создало неограниченный прокси (SSRF). При выделенном GPU-сервере потребуется специальный защищённый локальный прокси или туннель. *Обычный дешёвый VPS для работы сайта почти наверняка не подходит для полноценной современной разговорной модели.* Реальные требования по GPU/RAM определяются весами, размером модели, контекстом и количеством одновременных пользователей; измерить до закупки.

В обоих режимах при недоступности модели или тайм-ауте остаётся локальный сценарный ответ — никаких дополнительных списаний. Бот не выдаёт модельный ответ как подтверждённый факт и не делает вывод из неподтверждённых J1939 или OEM-кодов.

## Условия конфиденциальности и качества

1. Внешний ИИ начинает работать только если **серверная настройка разрешена** и пользователь **отдельно разрешил ИИ-обработку**. Для локальной модели в интерфейсе другое описание: сообщение остаётся в инфраструктуре TrakSOS.
2. Номера телефонов и VIN маскируются перед сохранением и отправкой в модель, но это **не делает любую переписку полностью обезличенной**. Не передавать PII клиентов, переговоры, документы или чаты мастеров без правового основания.
3. Для внешнего API требуется предварительно подтвердить юридические основания обработки, допустимость трансграничной передачи, договор с поставщиком и выполнение требований к локализации данных. До решения этих вопросов внешний режим не включать.
4. `store: false` при использовании Responses API — настройка параметров хранения у провайдера, не обещание нулевого хранения, локализации или соблюдения законодательства само по себе.
5. Отдельно проверять, что модель не подменяет универсальный код OBD-II ошибкой EBS, ECAS, ABS или SPN/FMI, не советует опасный ремонт, не выдаёт гипотезу за заводской диагноз.
6. Бот не покупает услуги, не резервирует деньги, не снимает плату и не делает рекламу. Реальные резервы будущей консультации требуют отдельной банковской и юридической интеграции.
7. Собственный AI-сервер не равен «ИИ знает всё»: качества определяют модель, проверенные источники, контекст, безопасность и тестирование.

## Последовательность запуска

1. Прогнать CI на ветке, отдельный импорт CC0 и тестирование ролей.
2. Проверить качество ответов на подготовленных типовых запросах, включая неверный блок, неполный код, тормоза и недостоверные данные.
3. Определить юридически допустимого поставщика или собственную модель, бюджет, аппаратные требования и параметры приватности.
4. Проверить интерфейс на Android и ПК, отдельно согласие на ИИ.
5. После решения по провайдеру задать секреты/параметры в окружении **тестового** VPS и проверить работу без ключа, с отключением провайдера и при сетевом отказе.
6. Только после проверки правовых условий и мониторинга ограниченно включать API или модель; production без отдельного решения не менять.
