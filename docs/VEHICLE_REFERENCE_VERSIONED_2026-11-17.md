# TrackSOS — нормализованный справочник транспорта: изолированная основа

Связано с задачами #91/#92, общим релизным контролем #107.
Разработка: feature/vehicle-reference-versioned-20261117.  
**Это серверное ядро и закрытая песочница; не включено в production UI.**

## Почему отдельная ветка

Во время параллельной разработки выяснилось, что PR #138/#139 и ранее созданный
PR #141 повторяли финансовый модуль #123. PR #141 закрыт как дубликат
(история и код сохранены), чтобы не появилось три несовместимые миграции.
Данный справочник не трогает финансовые, дизайнерские, Android, курьерские,
диспетчерские и login-файлы чужих PR.

## Новая структура

Миграция 260 создаёт только:
- vehicle_ref_sources — источник, точная лицензия, URL, обоснование права
  хранения и распространения, ручное административное утверждение;
- vehicle_ref_snapshots — версия, SHA-256, статус staged/active/retired,
  кол-во марок/моделей; в один момент активна только одна версия источника;
- vehicle_ref_brands — категория, стабильный ключ марки, русское/локализованное
  название, проверенные псевдонимы;
- vehicle_ref_models — принадлежность модели ровно одной категории и марке,
  годы выпуска, псевдонимы;
- vehicle_ref_registry_events — неизменяемая история регистрации, согласования,
  публикации, отката и отзыва прав, с автором и причиной.

Исторические марки и модели не переписываются. Отмена прав на источник
мгновенно убирает его из публичной выборки; архив истории сохраняется.
Каждое действие дополнительно проходит через audit_log.

## Контроль источников

Пустой справочник — правильное начальное состояние: не скачиваем и не
публикуем сторонние каталоги без подтверждённых прав.
Нет выдуманного API, VIN-декодера или «стопроцентной применяемости».
Не утверждаем, что государственный или коммерческий источник разрешает
перераспространение, пока его условия не проверены.

Порядок: админ регистрирует источник с HTTPS-адресом первоисточника и
лицензии/разрешения, подробно фиксирует правовую основу → отдельно подтверждает
права → загружает полный JSON-снимок → получает staged и SHA-256 → только после
ревью вручную активирует. При конфликте ключа/версии хеш должен совпадать,
иначе отказ; повтор успешного импорта не создаёт новую версию.

Границы: максимум 1500 марок, 12000 моделей в одном снимке; для более
крупного лицензированного каталога — отдельные источники/снимки и импорт
в несколько пакетов. Данные в целиком подготовленной версии, без
тихой перезаписи предыдущего релиза.

## Категории и двухэтапный выбор

Категории: truck, trailer, bus, van, passenger.
Сперва выбирается марка (brand key), затем только связанные с ней модели.
Смена марки обнуляет/инвалидирует прежний выбор модели при дальнейшей
UI-интеграции. Год проверяется по диапазону (если источник его указал).
Строгая проверка не заменяет VIN-применяемость деталей или техническую
экспертизу доработанного автомобиля.

Предустановки по задачам #91/#92:
- владелец/водитель — грузовые, прицепы, автобусы, фургоны;
- выездной мастер — легковые и фургоны по умолчанию, с опциональным
  расширением на грузовые специализации; **существующих грузовых мастеров
  автоматически не ограничивать**;
- эвакуаторщик — грузовые/прицепы/автобусы/фургоны;
- страховщик, СТО и техосмотр — без глобального навязывания марки,
  во вложенных рабочих сценариях возможны все категории.

При конфликте двух источников по одинаковому ключу возвращается
конфликт, а не автоматически «исправленная» модель. Каталоги не
открываются при ещё не опубликованном или отозванном источнике.

## Доступ и песочница

Импорт/активация/отзыв/история лицензий: только действующий admin.
Чтение утверждённых названий марки/модели ограничено контекстом роли
и разрешёнными категориями. Финансовые суммы, ФИО и VIN в этот модуль
не импортируются и не кэшируются.

Нет API-маршрутов в server/src/app.ts, изменений server/src/services/fleet.ts,
web/src/dict.ts, карточек заказа или Android. Ранее сохранённые
строки brand/model в таблице vehicles остаются как были. Миграция 260
добавляет только новые таблицы. Перед публичной интеграцией потребуются
механизмы перехода для действующих автомобилей, проверка совместимости
с регистрацией, страхованием и сервисными заявками.

Скрипт server/src/ops/vehicleReferenceCli.ts **отказывается** работать,
если не заданы SANDBOX_INSTANCE=true, VEHICLE_REF_SANDBOX_CLI=yes,
VEHICLE_REF_ADMIN_ID действующего админа тестовой БД и отдельный
DATABASE_URL с именем sandbox. Также действуют защиты config.ts
(log SMS, log push, mock payments, раздельные настройки).

### Пример файла fictitious-source.json (вымышленные сведения)

    {
      "key": "internal-demo-1",
      "name": "Internally authored sample",
      "originUrl": "https://example.org/test-fixture",
      "licenseName": "Internal fictional sample",
      "licenseUrl": "https://example.org/permissions",
      "rightsEvidence": "Written internal confirmation of redistribution rights for synthetic sample records"
    }

### Пример fictitious-models.json (только проверка алгоритма)

    {
      "sourceRevision": "2026-11-demo",
      "brands": [{
        "category": "truck",
        "key": "example-motors",
        "name": "Пример Моторс",
        "aliases": ["Example Motors"],
        "models": [{
          "key": "example-500",
          "name": "Пример 500",
          "yearFrom": 2000,
          "yearTo": 2020
        }]
      }]
    }

После корректного рассмотрения прав из директории server/:

    npx tsx src/ops/vehicleReferenceCli.ts register-source /secure/fictitious-source.json
    npx tsx src/ops/vehicleReferenceCli.ts approve-source internal-demo-1 "Internal fictional sample rights verified"
    npx tsx src/ops/vehicleReferenceCli.ts stage internal-demo-1 /secure/fictitious-models.json
    npx tsx src/ops/vehicleReferenceCli.ts activate internal-demo-1 2026-11-demo "Reviewed and approved source data"
    npx tsx src/ops/vehicleReferenceCli.ts brands
    npx tsx src/ops/vehicleReferenceCli.ts models truck example-motors

**НЕ выполнять этот CLI на рабочей БД.** Примеры принадлежат только
вымышленной песочнице.

## Приёмка и следующие независимые шаги

После одного большого commit и только на disposable PostgreSQL:
- типы и основная CI, real PostgreSQL integration test, импорт без дублей;
- проверка версии/хеша, непубликация staged, откат источника;
- отзыв лицензии полностью скрывает результат;
- роль/категория/год, неверная модель другой марки;
- недопустимые алиасы, дубли, ошибки диапазонов, права администратора.

Следующие шаги ПОСЛЕ согласования дизайна и источников: подключить
защищённый endpoint для верифицированного справочника; перевести формы
марка→модель только по готовым активным источникам, не обрезая существующий
парк. Для незнакомой модели — ручной запрос, а не фиктивный VIN-каталог.
Вводить публичную реальную модель только с подтверждением владельца.


## Интеграция в единый кандидат (19.11.2026)

Серверное ядро, строгие проверки прав источника, миграция 260 и тесты перенесены в PR #199 без изменения публичного интерфейса, гаража, входа и рабочих заявок. Модуль **не подключён к пользовательским API** и не разрешает загрузку сторонних справочников без отдельного согласования и песочницы. После CI отдельно проверяются совместимость со существующим выбором марки/модели, доступ администратора и права на исходные данные. Это сохранение готового изолированного кода, **не выпуск каталога в production**.
