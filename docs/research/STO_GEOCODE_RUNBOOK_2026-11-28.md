# Массовое геокодирование справочника СТО

Использовать собственный локальный Nominatim с российским набором данных OSM или локальный шлюз к разрешённому оператором сервису, совместимому с Nominatim JSONv2. Публичный nominatim.openstreetmap.org запрещён в этом инструменте. Не устанавливать тяжёлую базу геокодера на рабочий VPS без оценки ресурсов; использовать отдельный компьютер/сервер. Подключение через локальный порт или туннель.

1. После штатной выкладки: Админ → Справочник СТО → Массовое определение координат → Выгрузить адреса JSON.
2. На машине с репозиторием и доступным собственным геокодером запустить (порт приведён как пример):

```bash
STO_NOMINATIM_URL=http://127.0.0.1:7070 npm -w server run geocode:sto -- /path/sto-geocode-queue.json /path/sto-geocode --confirm-reuse
```

Флаг подтверждает право хранения и использования данных; для OSM соблюдать ODbL, атрибуцию и применимые требования к производным базам. Не использовать сервис с лицензией, запрещающей хранение. Ссылки на объекты OSM записываются в результат. Документация: https://nominatim.org/release-docs/latest/api/Search/ ; https://operations.osmfoundation.org/policies/nominatim/ ; https://www.openstreetmap.org/copyright .

3. Файлы: .checkpoint.json — возобновление после сбоя с теми же параметрами; .results.json — только однозначные кандидаты точного дома; .review.json — все обработанные адреса, совпадения и причины отказа. Обрабатываются только простые адреса с регионом, населённым пунктом, улицей, номером дома. Неоднозначные, километровые и сложные адреса требуют отдельного разбора. Не считать совпадение адреса доказательством деятельности СТО или точного въезда.
4. Импортировать .results.json в админке. Координаты сохраняются в черновиках с проверкой ревизии и адреса. Затем проверить источник, фактический адрес и привязку здания; после этого использовать массовую публикацию. Никаких автоматических публичных точек.

При сбое повторить команду с тем же префиксом. Для повторного поиска ранее не найденных строк используйте новую выгрузку/новый префикс. Не переносить контрольный файл на другой endpoint. Инструмент не подключается к production-БД, не отправляет телефоны или личные сведения, не выполняет публикацию.
