# Этап реализации дополнительных диагностических интерфейсов
Добавлены 14 исследовательских записей кабелей/маршрутов с источниками в офлайн-справку, поиск по производителю. Ни одна запись не является распиновкой, разрешением или проверенной совместимостью. Точная идентификация будущего профиля: модель, номер блока, HW, SW, кабель, место, физический интерфейс. Пустой рабочий реестр; синтетические тесты отдельно проверяют отказ при несовпадении, запрет очистки без отдельной валидации и ремонта.
Добавлена переносимая C++ модель коммутации: all-off при старте, break-before-make, один бит активного пути, отказ при попытке смены активной шины, прекращение при разрыве связи, истечении lease, отсутствии кабеля или включённых фонарях, защёлка аппаратного отказа и сброс без автоматического подключения. WarningInput не разрешает TX. 100 ms и 2 s — параметры тестовой модели, не электрические номиналы. Модель не интегрирована в GPIO и USB bench BLE не может выбирать физический интерфейс. Ни программный guard, ни пользовательские флаги не заменяют физические блокировки и проверенные обратные сигналы.
Следующая обязательная граница: принципиальная схема, выбор точных трансиверов с документацией, реальный pin budget, fail-off при reset/отключении питания, питание отдельно от сигнальных шин, проверка обратной подачи и кабелей. До прохождения аппаратной проверки реальный обмен запрещён. Нижнее меню и утверждённый дизайн без изменений; новый поиск находится только внутри справки. CI тестирует Kotlin и C++ модели, не физическую защиту.
