# Защита Mini Diagnostic — обязательные условия выпуска
## Текущий статус
Репозиторий shipaka/traksos публичный по данным GitHub 26.11.2026. Не менять видимость общего проекта без решения владельца. Для защиты собственных алгоритмов и частных диагностических профилей требуется отдельный закрытый репозиторий/закрытое хранилище; опубликованную историю нельзя сделать неизвестной внешним лицам задним числом. Не коммитить секреты даже в закрытый репозиторий. Обфускация затрудняет разбор APK, но не гарантирует невозможность копирования офлайн-базы.
## Внедрено
Release: R8, сокращение ресурсов, отключённый debugger, отдельная конфигурация подписи из четырёх переменных доверенной среды. Без всех четырёх переменных собирается НЕподписанный контрольный release; частичная конфигурация отклоняется. PR CI собирает unsigned release для проверки R8, не публикует его, тестовый debug APK не является коммерческим релизом. Закрытый ключ не генерируется и не хранится в GitHub. Android без INTERNET, cleartext запрещён, backup и перенос данных исключены правилами. Пользователь может осознанно экспортировать собственные отчёты; запрета скриншотов или постоянной онлайн-активации нет. Статические тесты контролируют базовые настройки. В виртуальный InterfaceGuard добавлено отдельное условие authenticated, потеря которого отключает маршрут без автоматического восстановления; это модель, не настоящий криптографический сеанс.
## Обязательные условия до физического доступа
- На первом соединении локальная привязка конкретного прибора по физическому подтверждению и индивидуальному случайному секрету/ключу. Никаких универсальных PIN, общих ключей в APK и доверия по имени устройства/MAC/UUID. BLE LE Secure Connections с аутентифицированным способом привязки, проверка личности адаптера на прикладном уровне стандартной криптографией, свежие challenge и счётчики против повторов. Реализация и тестирование с Android и выбранным ESP32 ещё впереди. Ключ телефона хранить в Android Keystore. Возможность удалить привязку и восстановить доступ физически; не требовать интернет для каждого запуска. После потери сеанса аппаратное отключение; остановка безопасна даже при ошибке аутентификации. Протокол не даёт общего доступа к CAN или произвольным командам.
- ESP32: Secure Boot, шифрование flash, защита от отката, подписанные обновления, закрытие отладочных интерфейсов после проверок. Выбрать точную ревизию чипа и процедуру восстановления. eFuse необратимы; на текущей экспериментальной плате не прожигать. USB-only bench BLE v1.1 остаётся неаутентифицированным и виртуальным; запрещено переносить его в производственную силовую схему.
- Выпуск APK: собственный долгосрочный ключ, отдельное безопасное резервирование, проверка сертификата и подписи apksigner по доверенному отпечатку. Переменные TRAKSOS_MINI_KEYSTORE, TRAKSOS_MINI_STORE_PASSWORD, TRAKSOS_MINI_KEY_ALIAS, TRAKSOS_MINI_KEY_PASSWORD предоставляются локально, не публикуются. Пройти release-mode smoke tests, аудит зависимостей и проверку фактического манифеста. CI PR не должен иметь доступа к ключам выпуска. Любая сборка без проверенной подписи не распространяется как релиз.
- Для защиты коммерческой базы при необходимости отдельное решение о лицензировании: офлайн подписанная лицензия с восстановлением при смене телефона, без общих встроенных секретов. Это не DRM-гарантия: пользователь, которому доступны офлайн-данные, может извлечь их. Не блокировать безопасное выключение устройства при истечении лицензии. Реальные журналы хранить минимально, чувствительные локальные записи шифровать ключом Keystore до внедрения постоянной истории; копирование отчёта только по действию пользователя.
