# Инженерный инструмент просмотра журналов CAN
Офлайн-анализатор Python 3, не подключается к CAN и не отправляет кадры. Вход — уже существующий журнал классических CAN data frames в компактном формате candump с числовой меткой времени. Поддержаны 11/29-битные ID, 0–8 байт данных и дробные секунды до 9 цифр. Пример СИНТЕТИЧЕСКИЙ: (1.000001) can0 123#ABCD. Источник формата: https://github.com/linux-can/can-utils/blob/master/candump.c и https://manpages.debian.org/unstable/can-utils/candump.1.en.html.

Запуск из mini-diagnostic: python tools/can_trace.py example.log --output summary.json. Исходник не изменяется; JSON создаётся только в новом файле. Код возврата 0 — синтаксически чистый непустой журнал, 2 — пустой или с отклонёнными строками/нарушением времени, 1 — ошибка ввода/вывода или лимит. Файлы до 16 MiB/200 тыс. кадров. Вывод: контрольная сумма исходника, перечень ID и размеров полезных данных, счётчики отклонений, номера первых проблемных строк. RTR, CAN FD, error frames, drop markers и прочие неподдерживаемые строки не отбрасываются незаметно. Направление TX/RX неизвестно, полнота захвата не доказана, даже если parseClean=true. Нет догадок о производителе, адресации или DTC; это не парсер ECU. Сам оригинальный журнал сохраняется отдельно. Перед передачей удалить личные данные, исключить посторонний обмен. Использовать только собственный неподвижный стенд с согласованным физическим интерфейсом. Пассивный захват ESP32 ещё не реализован, не подключать существующую USB-прошивку к прицепу.

Тесты: python -m unittest discover -s tools -p 'test_*.py'.

## Проверка комплекта стендовых доказательств
`python tools/bench_evidence.py check path/to/session --output review.json` проверяет строгий manifest.json, контрольные суммы и целостность файлов, использует can_trace.inspect для классического CAN. `python tools/bench_evidence.py inventory path/to/session` выводит список допустимых файлов с SHA-256 для заполнения манифеста. Ничего не подключает и не изменяет исходники. Шаблон и инструкция: ../docs/bench-evidence-package.md. Успешная проверка — только структурная готовность к ручному разбору, не подтверждение физического источника или профиля.
